# 후추 디펜스 3D·애니메이션·리텐션 리뉴얼 설계

- 작성일: 2026-07-21
- 대상 브랜치: `codex/mobile-td-mvp`
- 상태: 사용자 권장안 승인 완료, 구현 계획 작성 전

## 1. 목표

기존 Canvas 2D 타워 디펜스의 전투 규칙은 유지하면서 화면 전체를 동일한 Blender 제작 규격의 2.5D 에셋으로 통일한다. 적 이동과 공격 효과에 애니메이션을 추가하고, 모바일 배치 UX와 결과 화면을 강화해 한 판의 가독성과 재도전 동기를 높인다.

이번 리뉴얼은 다음 사용자 피드백을 모두 포함한다.

- 맵, 길, 입구, 간식 보물상자, 타워, 캐릭터, 투사체, 폭발을 동일한 3D 스타일로 통일
- 모든 개별 에셋의 불투명 사각 배경 제거
- 일반 적 보행과 요정 날개짓 구현
- 일반 적 HP는 피격 후 잠시만 표시하고 보스 HP는 항상 보라색으로 표시
- 타워를 한 타일 크기로 통일하고 길 주변 8칸에만 배치
- 후추와 덕배는 캐릭터만 렌더하고 워터볼·파이어볼은 별도 투사체로 분리
- 화살 타워와 화살 투사체가 공격 방향을 반영
- 배치를 선택·미리보기·확정·취소의 두 단계 흐름으로 변경
- 보스 등장 연출과 점수 기반 결과 화면 추가
- HUD와 전체 레이아웃을 Material 3 원칙으로 통일

## 2. 범위 밖

- Three.js 또는 WebGL 실시간 3D 엔진 전환
- 타워 업그레이드, 판매, 이동
- 신규 스테이지와 신규 타워 추가
- 계정 로그인, 서버 랭킹, 클라우드 저장
- 기존 전투 밸런스 수치의 전면 재조정

## 3. 핵심 아키텍처

### 3.1 렌더링 방식

게임은 `CanvasRenderingContext2D`를 유지한다. Blender MCP로 모델링한 결과를 투명 PNG와 가로형 프레임 시트로 렌더한 뒤 Canvas에 합성한다. simulation, fixed-step loop, 터치 입력, DOM HUD 구조는 보존하고 투영·에셋·상태 표현을 확장한다.

런타임 렌더 순서는 다음과 같다.

1. 2.5D 지형 타일
2. 지면 효과와 배치 가이드
3. 간식 보물상자, 타워, 적을 발 위치 기준으로 깊이 정렬
4. 투사체와 타격·폭발 효과
5. 보스 등장 오버레이와 별도의 게임 일시정지 오버레이
6. DOM 기반 Material 3 HUD와 결과 화면

### 3.2 2.5D 격자 투영

논리 월드는 기존 20열 × 10행 정수 격자와 완전 직각 경로를 유지한다. 화면에서는 동일한 직교 카메라로 렌더한 대각선 타일로 표현한다.

기본 투영은 다음 형태를 사용한다.

```text
screenX = originX + (worldX - worldY) * tileWidth / 2
screenY = originY + (worldX + worldY) * tileHeight / 2
```

- `tileWidth : tileHeight`는 2:1을 기본으로 한다.
- 포인터 입력은 역변환 후 diamond 경계 검사를 거쳐 셀을 결정한다.
- 월드 좌표의 상하좌우 이동은 화면의 네 대각선 방향과 일치한다.
- 타일과 엔티티의 깊이는 `worldX + worldY`, 발 위치, 안정적인 entity id 순으로 정렬한다.
- 레이아웃은 844×390을 기준으로 전체 맵이 보이도록 맞추고, 다른 가로 비율에서는 letterbox를 허용한다.

## 4. Blender 에셋 규격

### 4.1 공통 규칙

- 하나의 직교 카메라, key/fill/rim 조명, 색상 팔레트를 모든 컬렉션이 공유한다.
- Blender의 Film Transparent를 사용하며 이미지 네 모서리의 alpha는 0이어야 한다.
- 사각형 배경판은 렌더하지 않는다.
- 접지 그림자는 투명 alpha 위에만 존재하고 타일 바깥을 과도하게 침범하지 않는다.
- pivot과 렌더 anchor는 발 또는 타일 중심 하단으로 통일한다.
- 원본 프레임은 256×256, 모바일 런타임 프레임은 128×128로 관리한다.
- 프레임 시트는 한 방향의 프레임을 가로로 연결하고 manifest가 frame count, anchor, fps를 선언한다.
- 일반 적과 모든 타워의 논리·시각 footprint는 1타일이다.
- 미노타우르스는 논리 footprint 1타일을 유지하며 시각적으로 최대 1.25타일까지 돌출할 수 있다.

### 4.2 모듈형 맵 키트

필수 3D 타일은 다음과 같다.

- 잔디 기본 타일과 색상 차이만 있는 잔디 변형 2종
- 무늬 없는 직선 길 2방향
- 무늬 없는 코너 길 4방향
- 길의 시작을 알리는 입구 타일
- 간식 보물상자 받침 타일

길은 기존 요구대로 무늬를 넣지 않는다. 입체감은 낮은 단차, bevel, 부드러운 접지 그림자로만 표현한다. 격자 가독성은 타일 사이의 얇은 재질 경계로 확보하며 별도의 평면 Canvas 격자선을 주 표현으로 사용하지 않는다.

최종 목표물은 과자와 뼈다귀가 가득한 3D 보물상자로 제작한다. 상자는 마지막 경로 셀에 고정하고 길과 같은 카메라·조명을 사용한다.

### 4.3 타워

- 슬로우 타워: 1타일 구조물, 투명 배경, 별도 지면 오라 사용
- 화살 타워: 북동·남동·남서·북서 4방향 정적 본체
- 덕배: 캐릭터만 포함한 4방향 정적 본체, 파이어볼 제거
- 후추: 캐릭터만 포함한 4방향 정적 본체, 워터볼 제거

화살·덕배·후추는 현재 타깃 벡터를 4방향으로 양자화해 본체 방향을 선택한다. 타깃이 없을 때는 마지막 공격 방향을 유지하며 최초 방향은 남동이다.

### 4.4 적 애니메이션

- 슬라임, 오크, 골렘, 미노타우르스: 4방향 × 보행 6프레임 × 8fps
- 요정: 4방향 × 날개짓 8프레임 × 12fps
- 슬라임은 보행 대신 압축·복원과 작은 전진 바운스로 움직임을 표현한다.
- 적마다 `id` 기반 위상 차이를 적용해 같은 종류가 완전히 같은 박자로 움직이지 않게 한다.
- 애니메이션 프레임 선택은 simulation 위치에 영향을 주지 않는 순수 렌더 함수다.

### 4.5 투사체와 폭발

- 화살: 8방향 투명 3D 스프라이트. projectile velocity로 가장 가까운 방향을 선택한다.
- 파이어볼: 비행 4프레임 루프와 타격 폭발 8프레임
- 워터볼: 비행 4프레임 루프와 물보라 폭발 8프레임
- 화살 타격: 작은 3D 파편 4프레임
- 슬로우 효과: 별도 3D 룬/서리 파동 시트

파이어볼은 빠른 주황색 core와 짧은 ember trail, 워터볼은 큰 청록색 core와 회전 highlight를 갖는다. 폭발은 alpha·scale·frame 애니메이션을 함께 사용하고 2~4px의 짧은 화면 흔들림을 추가한다. `prefers-reduced-motion`에서는 화면 흔들림과 과도한 scale 변화를 제거한다.

## 5. 전투 표현과 상태

### 5.1 적 HP

- 일반 적은 마지막 피격 시점부터 2.5초간 HP를 표시한다.
- 다시 피격되면 2.5초 타이머를 갱신한다.
- 미노타우르스 HP는 출현 후 사라질 때까지 항상 표시한다.
- 일반 HP 색은 초록 → 노랑 → 빨강을 유지한다.
- 보스 HP 배경과 채움은 보라색 계열을 사용하고 `BOSS` label을 함께 표시한다.
- HP 시간은 game elapsed time을 기준으로 하며 pause와 세로 회전 차단 중에는 감소하지 않는다.

이를 위해 적 상태에 `lastHitAtSeconds`를 추가하고 projectile 피해가 실제 적용된 시점에만 갱신한다.

### 5.2 보스 등장

미노타우르스가 처음 spawn되는 fixed step에서 `boss-spawn` event를 1회 발생시킨다.

- 1.2초 보라색 vignette
- 상단 또는 중앙의 `보스가 나타났어요!` 배너
- 2회의 짧은 화면 흔들림
- 전용 합성 효과음
- 보스 이름과 보라색 HP 강조

연출 중에도 simulation은 계속 진행한다. 이벤트는 렌더 프레임이 건너뛰어져도 유실되지 않도록 기존 frame event buffer를 통해 전달한다.

## 6. 타워 배치 UX

### 6.1 배치 가능 셀

타워는 다음 조건을 모두 만족해야 배치할 수 있다.

- 맵 범위 안
- 경로 셀이 아님
- 다른 타워가 점유하지 않음
- 최소 하나의 경로 셀과 Chebyshev distance 1, 즉 상하좌우 또는 대각선으로 맞닿음

입구와 간식 보물상자 셀은 경로이므로 배치할 수 없다.

### 6.2 두 단계 배치

1. 하단에서 타워를 선택한다.
2. 유효한 인접 셀을 탭한다.
3. 해당 셀에 70% alpha의 3D ghost와 사거리 가이드를 표시한다.
4. 하단에 Material 3 `배치`와 `취소` 버튼을 표시한다.
5. `배치`를 누를 때만 골드를 차감하고 타워를 생성한다.
6. `취소`는 골드와 simulation 상태를 바꾸지 않고 pending 상태만 지운다.

배치 미리보기 중 전투는 계속 진행한다. 사거리는 2.5D 투영에 맞춘 반투명 ellipse와 범위 안 타일 tint로 표시한다. 유효 셀은 청록색, 무효 셀은 빨간색으로 나타낸다. 확정·취소·타워 선택 변경·게임 종료 직후 pending 상태와 사거리 가이드를 모두 지운다. 설치 완료된 타워를 탭해도 사거리나 업그레이드 UI를 열지 않는다.

## 7. Material 3 UI

외부 UI 라이브러리를 추가하지 않고 Material 3의 토큰과 상호작용 원칙을 CSS와 DOM 컴포넌트에 적용한다.

### 7.1 디자인 토큰

- 4px 기반 spacing scale
- surface, surface-container, primary, secondary, tertiary, error 색상 토큰
- 12px·16px·24px shape 토큰
- elevation 1~3 shadow 토큰
- pressed, selected, disabled state layer
- 최소 44×44px 터치 영역
- system rounded font와 tabular number

### 7.2 상단 HUD

- 골드, 체력, 웨이브를 동일한 높이·padding·폰트·숫자 정렬의 stat chip으로 표시
- 정지, 속도, 소리 버튼을 동일 크기의 icon button으로 통일
- safe-area와 작은 가로 화면에서도 좌우 margin이 동일하도록 한다.

### 7.3 하단 명칭

표시 이름은 다음으로 고정한다.

- `슬로우 타워`
- `화살 타워`
- `덕배`
- `후추`

배치 확인 상태에서는 타워 카드 위에 action bar를 추가하고 `배치`, `취소`, 가격을 표시한다.

## 8. 점수와 리텐션

### 8.1 기록 항목

게임 상태는 다음 통계를 누적한다.

- 처치 수
- 완료한 웨이브 수
- 남은 기지 체력
- 경로를 통과한 적 수
- 보스 처리 여부
- 플레이 시간 또는 승리 시 클리어 시간

### 8.2 점수 공식

```text
waveScore = completedWaves * 500
killScore = defeatedEnemies * 25
hpScore = remainingBaseHp * 100
bossScore = bossDefeated ? 1500 : 0
timeBonus = victory ? max(0, 3000 - floor(clearSeconds * 5)) : 0
totalScore = waveScore + killScore + hpScore + bossScore + timeBonus
```

점수는 음수가 될 수 없으며 모든 항목을 정수로 표시한다.

별 등급은 모든 완료된 플레이에 1~3개를 부여한다.

- 1개: 0~6,999점
- 2개: 7,000~9,999점
- 3개: 10,000점 이상

### 8.3 로컬 기록

버전이 있는 localStorage schema에 다음 값을 저장한다.

- 최고 점수
- 최단 클리어 시간
- 총 도전 횟수
- 총 승리 횟수
- 음소거 설정

기존 `bestClearSeconds`와 `muted` 값은 새 schema로 마이그레이션한다. 손상된 값은 안전한 기본값으로 복구하며 게임 시작을 막지 않는다.

### 8.4 결과 화면

승리 제목은 `간식 창고를 지켜줘서 고마워요`로 표시한다.

패배 제목은 `간식 창고가 다 털려버렸어요`로 표시한다.

두 화면 모두 다음을 포함한다.

- 큰 최종 점수와 1~3개 별
- 최고 기록 갱신 시 `새 최고 기록` badge
- 웨이브, 처치, 남은 체력, 보스 처리, 시간, 시간 보너스의 score breakdown
- 누적 최고 점수, 최단 클리어, 총 도전, 총 승리
- 다음 별 또는 최고 점수까지 남은 점수를 보여주는 다음 목표
- 재도전 primary button

승리 화면은 짧은 confetti와 따뜻한 색상을 사용한다. 패배 화면은 과도하게 침울한 표현 대신 보물상자가 열린 연출과 `다음에는 더 오래 지킬 수 있어요` 안내를 사용한다. reduced motion에서는 confetti와 count-up을 즉시 완료한다.

## 9. 데이터 흐름과 컴포넌트 경계

### 9.1 simulation

- 적의 위치, HP, 마지막 피격 시각, 처치·누수·보스 처리 통계를 소유한다.
- `boss-spawn`, `shot`, `hit`, `leak`, `enemy-defeated` event를 생성한다.
- 점수 계산 입력을 제공하지만 DOM이나 sprite frame을 알지 못한다.

### 9.2 runtime/UI state

- 선택한 타워와 `pendingPlacement`를 소유한다.
- placement confirm/cancel을 simulation command로 변환한다.
- frame event를 VFX, audio, boss presentation으로 변환한다.
- 결과 통계를 score calculator와 preferences store에 전달한다.

### 9.3 renderer

- projection, inverse projection, depth sorting을 담당한다.
- manifest에서 방향·프레임·anchor를 조회한다.
- animation은 elapsed time과 entity id로 결정하고 simulation을 변경하지 않는다.

### 9.4 HUD

- Material 3 DOM과 접근성 상태를 담당한다.
- 점수 계산이나 배치 유효성 규칙을 직접 구현하지 않는다.

## 10. 오류 처리와 성능

- 핵심 맵·타워·목표물 에셋이 빠지면 ready 화면 대신 재시도 가능한 오류 화면을 표시한다.
- 애니메이션의 후속 프레임만 빠진 경우 frame 0으로 대체하고 게임은 계속한다.
- 이미지 preload는 진행률을 표시하며 같은 URL을 중복 로드하지 않는다.
- DPR은 2로 제한한다.
- 모든 스프라이트 시트는 시작 전에 decode하고 전투 중 네트워크 요청을 발생시키지 않는다.
- 정적 타일은 offscreen canvas에 한 번 합성하고 레이아웃이나 DPR이 바뀔 때만 다시 만든다.
- 화면 밖 effect와 alpha 0 effect는 즉시 제거한다.
- reduced motion 설정은 보행 자체를 제거하지 않고 흔들림, count-up, 과도한 scale만 줄인다.

## 11. 테스트 설계

### 11.1 단위 테스트

- 2.5D projection/inverse projection round trip과 diamond 경계
- 모든 경로 셀 타입의 직선·코너 방향 분류
- 길 주변 8칸 배치 허용, 먼 셀·경로·점유 셀 거부
- pending placement의 선택·확정·취소·자동 정리
- 확정 전 골드 불변과 확정 후 한 번만 차감
- 일반 HP 2.5초 노출과 pause 시간 동결
- 보스 HP 상시 노출과 보라색 style token
- boss spawn event 1회 보존
- 4방향 본체와 8방향 화살 양자화
- 보행·날개·투사체·폭발 frame 선택
- 점수 공식, 별 임계값, 최고 기록 갱신
- preferences 이전 schema 마이그레이션과 손상값 복구
- 결과 문구와 하단 타워 명칭

### 11.2 렌더·에셋 계약 테스트

- manifest의 모든 파일 경로와 frame count 존재
- runtime PNG 프레임 크기 128×128
- alpha corner가 투명하고 anchor가 manifest 범위 안
- 타워와 일반 적의 draw footprint가 1타일
- depth order와 보스 visual overhang
- 설치 완료 후 range layer가 사라짐

### 11.3 E2E

- 844×390 가로 화면에서 타워 선택 → 유효 셀 미리보기 → 취소
- 유효 셀 미리보기 → 확정 → 골드 차감 및 range 숨김
- 길에서 먼 셀과 길 셀 배치 거부
- 전투가 pending placement 중에도 진행
- 피격된 일반 HP가 나타났다가 2.5초 뒤 사라짐
- 보스 등장 배너, 보라색 HP, 보스 처리 통계
- 승리·패배의 새 문구, 점수 breakdown, 기록 저장, 재시작
- 세로 화면 차단과 reduced motion 회귀
- 브라우저 console error와 page error가 없음

## 12. 에셋 승인 게이트

구현은 다음 두 단계로 나눈다.

### 12.1 대표 시안

Blender MCP로 다음 contact sheet를 먼저 만든다.

- 잔디·직선길·코너길·입구·보물상자
- 슬로우·화살·덕배·후추의 1타일 투명 렌더
- 일반 적 보행 대표 프레임과 요정 날개짓 대표 프레임
- 8방향 화살, 파이어볼, 워터볼
- 화살 타격, 불 폭발, 물 폭발 대표 프레임

사용자가 이 contact sheet를 승인하기 전에는 전체 방향·전체 프레임 batch와 게임 연결을 진행하지 않는다.

### 12.2 전체 생성과 연결

승인 후 동일한 Blender scene rig로 전체 방향·프레임을 렌더하고 manifest를 생성한다. 에셋 계약 검증을 통과한 뒤 projection, simulation state, placement UX, Material 3 HUD, 점수 화면 순으로 연결한다.

## 13. 완료 기준

- 런타임 화면에서 불투명 사각 배경을 가진 게임 에셋이 없다.
- 맵과 모든 유닛·목표물·투사체·폭발이 동일한 2.5D 조명과 카메라 스타일을 사용한다.
- 모든 일반 타워와 일반 적이 한 타일 footprint를 지킨다.
- 적 보행, 요정 날개짓, 방향성 화살, 분리된 파이어볼·워터볼이 실제 전투에서 동작한다.
- 일반 HP, 보스 HP, 보스 등장, 두 단계 배치가 정의된 시간과 상태 규칙을 지킨다.
- 결과 화면이 점수·별·최고 기록·클리어 또는 생존 시간·보스 처리 여부를 보여준다.
- 요청된 한국어 문구와 타워 이름을 정확히 사용한다.
- Material 3 spacing, typography, shape, elevation, state layer가 HUD 전반에 일관되게 적용된다.
- 단위 테스트, build, 모바일 E2E, visual QA, production debug-marker 검사가 모두 통과한다.
