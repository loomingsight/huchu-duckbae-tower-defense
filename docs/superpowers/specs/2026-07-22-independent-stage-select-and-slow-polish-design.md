# 독립 스테이지 선택 화면 및 슬로우 타워 표현 설계

## 상태

- 사용자 승인: 2026-07-22
- 선택안: 기존 런타임 상태와 preferences v3를 재사용하는 독립형 선택 화면
- 검증 정책: E2E 제외, 단위 테스트·타입 검사·프로덕션 빌드로 검증

## 목표

1. 앱 첫 진입과 전투 종료 시 전장을 가린 별도의 스테이지 선택 화면을 표시한다.
2. 6개 스테이지의 잠금·해금·클리어 상태, 최고 점수, 최단 클리어 시간을 한 화면에서 확인한다.
3. 클리어 시 다음 스테이지를 순차 해금하고 자동 선택한 뒤 선택 화면으로 복귀한다.
4. 해금된 스테이지를 선택해 골드·창고 내구도·타워·웨이브가 초기화된 새 게임을 시작한다.
5. 슬로우 타워의 주기적 동심원이 실제 사정거리까지 퍼지게 하고 타워 표시 크기를 10% 줄인다.
6. 신규 이미지 에셋, 라우트, 저장 스키마를 추가하지 않는다.

## 선택한 접근

현재 `ready`, `victory`, `defeat` 상태에서 사용하던 오버레이를 불투명한 독립형 스테이지 선택 화면으로 승격한다. 별도의 `selecting` 런타임 상태나 HTML 경로는 추가하지 않는다.

- `ready`: 앱 첫 진입과 새 게임 전 스테이지 선택
- `victory`: 결과와 해금된 다음 스테이지를 함께 표시
- `defeat`: 결과와 현재까지 해금된 스테이지를 함께 표시
- `playing`, `paused`: 선택 화면을 숨기고 현재 게임 화면 표시

이 방식은 기존 `createGame(selectedStageId)` 초기화 경로와 preferences v3를 그대로 사용하므로 상태 중복과 마이그레이션을 피한다.

## 스테이지 선택 화면

### 구성

- 전장을 완전히 가리는 불투명 화면
- 모바일 가로 화면에서 한눈에 확인할 수 있는 3열×2행 스테이지 카드
- 카드 정보
  - 스테이지 번호와 이름
  - `잠김`, `도전 가능`, `클리어` 상태
  - 최고 점수
  - 최단 클리어 시간
- 선택한 카드 강조
- 잠긴 카드는 `disabled`와 잠김 `aria-label` 적용
- 모든 조작 대상은 최소 44×44px 유지

### 기록 표시 규칙

- 잠김: `잠김`
- 해금됐지만 기록 없음: `기록 없음`
- 플레이했지만 미클리어: `최고 {점수}점 · 미클리어`
- 클리어: `최고 {점수}점 · 최단 {분:초}`

점수 `0`과 클리어 시간 `null`은 기록 없음으로 처리한다. 클리어 여부는 `bestClearSeconds !== null`로 판정한다.

### 흐름

1. 앱 시작 시 `highestUnlockedStage`를 기본 선택한 상태로 선택 화면을 표시한다.
2. 해금된 카드를 선택하면 선택 상태만 바꾸고 즉시 게임을 시작하지 않는다.
3. 주 버튼을 눌러 선택한 스테이지를 시작한다.
4. `createGame(selectedStageId)`가 기본 골드, 창고 내구도, 빈 타워, 첫 웨이브 상태를 생성한다.
5. 승리 시 결과를 저장하고 다음 스테이지를 해금·선택한 뒤 선택 화면을 표시한다.
6. 패배 시 결과를 저장하고 현재 스테이지가 선택된 선택 화면을 표시한다.

최종 실행 결과 패널은 선택 화면 하단에 유지해 점수, 클리어 시간, 보스 처리 여부를 확인할 수 있게 한다.

## 슬로우 타워 표현

### 동심원

- 기존 3초 간격과 0.6초 지속 시간은 유지한다.
- 시작 반지름은 기존 `0.35` 타일을 유지한다.
- 최종 반지름은 하드코딩된 시각 값이 아니라 `TOWER_CATALOG.slow.range`를 사용한다.
- 진행률 `0..1`에 대해 시작 반지름에서 실제 사정거리까지 선형 보간한다.

### 에셋 표시 크기

- 현재 공통 타워 표시 배율 `2.0`에서 슬로우 타워만 `1.8`로 변경한다.
- 다른 타워 배율은 유지한다.
- 배치 앵커와 타일 바닥 정렬은 변경하지 않는다.

## 코드 변경 범위

- `src/app/hud.ts`: 스테이지 카드 뷰 모델, 기록 포맷, 독립 선택 화면 마크업과 렌더링
- `src/app/GameApp.ts`: preferences 기록을 선택 화면 렌더링에 전달
- `src/styles.css`: 불투명 선택 화면과 3×2 카드 레이아웃
- `src/game/render/drawEffects.ts`: 실제 사정거리 기반 동심원 반지름
- `src/game/render/drawEntities.ts`: 타워 종류별 표시 크기
- 관련 단위 테스트와 `docs/backlog.md`

## 테스트 전략

### 단위 테스트

- 스테이지 카드의 잠금·도전 가능·클리어 상태와 기록 문구
- 선택/잠김 접근성 속성
- 동심원 진행률 0과 1의 반지름
- 슬로우 타워 표시 배율이 다른 타워보다 정확히 10% 작은지 확인
- 기존 상태별 주 버튼 문구와 게임 초기화 회귀 확인

### 정적 검증

- TypeScript 타입 검사
- 프로덕션 빌드
- 빌드 결과 JS/CSS 경로가 Vite base를 따르는지 확인

Playwright와 기타 E2E는 사용자 승인에 따라 실행하지 않는다.

## 배포

검증 완료 후 `main`에 커밋·푸시한다. GitHub Pages 워크플로의 정확한 푸시 SHA가 성공한 뒤 공개 URL과 주요 JS 번들의 HTTP 200 응답을 확인한다.
