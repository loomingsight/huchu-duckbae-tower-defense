# 나이트메어 6스테이지 확장 설계

## 상태

- 사용자 승인: 2026-07-23
- 대상: 기존 6개 스테이지를 노멀로 유지하고 별도 나이트메어 6개 스테이지 추가
- 에셋 정책: 2D 도안 승인 → Blender MCP 3D 승인 → 게임 통합
- 검증 정책: E2E 제외, 단위 테스트·타입 검사·프로덕션 빌드·에셋 검증·수동 스크린샷
- 난이도 목표: 나이트메어 1은 노멀 6 수준, 나이트메어 6은 숙련자도 1~3회 재도전

## 목표

1. 노멀과 나이트메어를 독립적인 6스테이지 진행으로 제공한다.
2. 기존 노멀 밸런스와 저장 기록은 유지한다.
3. 나이트메어 전용 적 5종, 6개 직각 맵, 다크 테마와 특성 애니메이션을 추가한다.
4. 기존 타워 4종과 타워 배치·업그레이드 없는 규칙은 유지한다.
5. 난이도별 해금, 기록, 점수와 별을 명확히 분리한다.
6. HTML Canvas 런타임에 맞춰 Blender 모델을 정면 투명 스프라이트로 렌더해 모바일 성능을 지킨다.
7. 향후 다른 난이도를 추가해도 숫자 ID 변환이나 조건문이 늘어나지 않는 데이터 구조를 만든다.

## 범위에서 제외

- 신규 타워, 타워 업그레이드, 영구 성장 및 스테이지 간 자원 승계
- 분기 경로, 다중 입구, 무작위 웨이브 및 동적 난이도 보정
- 기존 노멀 6스테이지의 적·맵·타워 밸런스 변경
- 실시간 WebGL 3D 모델 로딩
- 사용자 승인 전 후보 에셋의 런타임 연결
- Playwright 및 기타 E2E 실행

## 선택한 구조

난이도와 스테이지 번호를 합친 안정적인 키를 사용한다. 내부에서 나이트메어를 스테이지 7~12로 취급하지 않는다.

```ts
const GAME_MODES = ['normal', 'nightmare'] as const;
type GameMode = (typeof GAME_MODES)[number];

const STAGE_NUMBERS = [1, 2, 3, 4, 5, 6] as const;
type StageNumber = (typeof STAGE_NUMBERS)[number];
type StageKey = `${GameMode}-${StageNumber}`;

type StageDefinition = Readonly<{
  key: StageKey;
  mode: GameMode;
  number: StageNumber;
  name: string;
  themeId: StageThemeId;
  map: StageMap;
  waves: readonly Wave[];
  startingGold: number;
  baseHp: number;
  rewardMultiplier: number;
  scoreMultiplier: number;
  hpMultiplier: number;
  speedMultiplier: number;
  spawnIntervalMultiplier: number;
  countMultiplier: number;
  twoStarScore: number;
  threeStarScore: number;
}>;
```

`STAGE_CATALOG`을 유일한 정의 원본으로 둔다. 시뮬레이션, 렌더러, HUD와 저장 로직은 모두 `game.stageKey`로 같은 정의를 조회한다. 전역 mutable active-stage 값과 `stageId > 6` 같은 분기를 만들지 않는다.

기존 숫자 `StageId` 호환 함수는 마이그레이션 경계에서만 사용하고 신규 런타임 계약에는 전파하지 않는다.

## 선택 및 해금 규칙

- 앱을 새로 시작하거나 게임이 끝나면 독립 스테이지 선택 화면을 표시한다.
- 선택 화면 상단에 `노멀`과 `나이트메어` 탭을 둔다.
- 각 탭은 3×2 카드로 6개 스테이지를 표시한다.
- 노멀 6을 클리어하기 전에도 나이트메어 탭은 보이지만 잠금 상태다.
- 노멀 6 클리어 시 `nightmare-1`을 해금한다.
- 나이트메어는 클리어할 때마다 다음 번호를 순차 해금한다.
- 나이트메어 6 클리어 시 `심연의 수호자` 배지를 기록한다.
- 패배, 높은 패배 점수 및 보스 미처리는 해금에 영향을 주지 않는다.
- 게임 플레이 중에는 모드나 스테이지를 바꿀 수 없다.

카드에는 상태, 최고 점수, 최고 별, 최단 클리어 시간을 표시한다. 클리어 후 선택 화면으로 돌아오면서 새로 열린 카드에 한 번만 짧은 해금 애니메이션을 재생한다.

잠긴 탭과 카드는 실제 `disabled` 상태와 접근 가능한 잠금 설명을 함께 제공한다. 모든 조작 대상은 최소 44×44 CSS px을 유지한다.

## preferences v4와 이전

저장 키는 `huchu-defense.preferences.v4`로 올린다. 기존 v3 키는 삭제하지 않는다.

```ts
type StageRecord = Readonly<{
  bestScore: number;
  bestClearScore: number;
  bestClearSeconds: number | null;
  bestStars: 0 | 1 | 2 | 3;
  bossDefeated: boolean;
}>;

type GamePreferencesV4 = Readonly<{
  muted: boolean;
  totalAttempts: number;
  totalVictories: number;
  highestUnlockedByMode: Readonly<{
    normal: StageNumber;
    nightmare: 0 | StageNumber;
  }>;
  stageRecords: Partial<Record<StageKey, StageRecord>>;
  badges: readonly 'abyss-guardian'[];
}>;
```

v3에서 v4로 처음 읽을 때 다음처럼 이전한다.

1. 기존 `stageRecords[1..6]`을 `normal-1..normal-6`으로 복사한다.
2. `bestClearSeconds`가 있으면 기존 `bestScore`를 보수적으로 `bestClearScore`로 사용한다.
3. 클리어 기록의 노멀 별은 기존 7,000/10,000점 기준으로 파생하고, 미클리어 기록은 0별로 둔다.
4. 클리어 기록은 보스를 처리한 것으로 간주한다. 미클리어 기록에서는 보스 여부를 추정하지 않는다.
5. `normal` 해금 상태, 음소거, 총 도전 및 총 승리를 그대로 보존한다.
6. `normal-6.bestClearSeconds`가 있을 때만 `nightmare-1`을 해금한다.
7. 손상되거나 범위를 벗어난 필드는 현재 정규화 정책과 동일하게 안전한 기본값으로 복구한다.

최고 점수는 승패와 무관하게 갱신할 수 있지만, `bestClearScore`, 별, 최단 시간, 해금과 배지는 승리에서만 갱신한다. 같은 결과를 두 번 기록해도 해금과 배지가 중복되지 않도록 갱신은 멱등적이어야 한다.

## 나이트메어 공통 규칙

- 시작 골드: `280G`
- 창고 내구도: `12`
- 웨이브: `10`
- 처치 골드 배율: `0.85`
- 최종 점수 배율: `1.5`
- 타워 가격·사거리·피해·공격 주기: 기존 값 유지
- 타워 배치: 경로와 Chebyshev 거리 1인 비경로 칸만 허용
- 나이트메어 웨이브에는 기존 노멀 적을 섞지 않고 신규 적 5종만 사용
- 모든 적과 보물은 이동 방향과 무관하게 정면을 유지
- 5웨이브: 엘리트 1마리
- 10웨이브: 리치 왕 1마리

최종 수치는 다음 계약을 따른다.

```text
최종 HP = 기본 HP × stage.hpMultiplier × (1 + waveIndex × 0.08) × variantHpMultiplier
이동량 = 기본 속도 × stage.speedMultiplier × slowMultiplier × auraMultiplier × variantSpeedMultiplier × dt
스폰 대기 = group.spawnInterval × stage.spawnIntervalMultiplier
처치 골드 = round(기본 보상 × 0.85 × variantRewardMultiplier)
```

가속 오라는 중첩하지 않고 남은 지속시간만 갱신한다. 모든 전투 타이머는 pause와 게임 속도 변경을 따르는 시뮬레이션 시간으로 계산한다. 렌더 애니메이션 시간은 전투 판정에 사용하지 않는다.

## 신규 적

내부 적 타입은 `shadowSlime`, `vampireBat`, `skeletonKnight`, `obsidianGolem`, `lichKing`으로 정의한다.

| 적 | HP | 속도 | 기본 보상 | 누출 | 전투 점수 |
|---|---:|---:|---:|---:|---:|
| 그림자 슬라임 | 90 | 1.10 | 본체 4G, 자식 각 2G | 1 | 본체 15, 자식 각 5 |
| 흡혈 박쥐 | 64 | 2.55 | 10G | 1 | 25 |
| 해골 기사 | 200 | 0.92 | 15G | 2 | 40 |
| 흑요석 골렘 | 620 | 0.44 | 28G | 3 | 75 |
| 리치 왕 | 3,500 | 0.46 | 150G | 10 | 보스 점수로 대체 |

표의 보상에 공통 0.85 배율을 한 번 적용한다. 그림자 슬라임 한 가족의 실제 총 보상은 본체 3G와 자식 각 2G인 7G다.

### 그림자 슬라임 분열

- 본체가 피해로 죽었을 때만 작은 슬라임 2마리를 같은 경로 진행도에 생성한다.
- 자식은 본체 최종 최대 HP의 35%, 본체 속도의 125%를 사용한다.
- 자식은 다시 분열하지 않는다.
- 본체가 창고에 도달하거나 이미 분열을 시작한 경우 중복 생성하지 않는다.
- 본체는 180ms 동안 눌린 뒤 두 방울이 좌우 시각 오프셋으로 튀어나온다. 실제 경로는 하나를 유지한다.
- 본체 15점과 자식 각 5점으로 가족 전체 전투 점수를 25점에 고정한다.

### 흡혈 박쥐 둔화 저항

- 둔화 강도의 50%를 저항한다.
- 슬로우 타워 배율 0.62가 적용되면 실제 배율은 `1 - (1 - 0.62) × 0.5 = 0.81`이다.
- 최초 둔화 시 보라색 날개 섬광과 얼음 고리가 깨지는 효과를 재생한다.
- 반복 피격 시 효과가 과도하게 번쩍이지 않도록 시각 피드백에만 0.8초 재생 제한을 둔다.

### 해골 기사 방패

- 최초 피해 이벤트 3회를 완전히 막는다.
- 슬로우 적용은 피해 이벤트가 아니므로 방패 횟수를 소모하지 않는다.
- 직접탄과 스플래시는 해당 적에 도달한 개별 피해 이벤트마다 정확히 한 번 소모한다.
- 등장 시 350ms 동안 반투명 방패가 펼쳐진다.
- 방어 시 120ms 점멸하고, 마지막 방어 후 240ms 파편 애니메이션으로 파괴된다.
- 방패 상태는 `shieldHitsRemaining`으로 시뮬레이션에 저장한다.

### 흑요석 골렘 손상 단계

- 별도의 피해 감소는 없고 높은 HP가 역할을 담당한다.
- HP 60%와 30%를 처음 통과할 때 한 번씩 갑옷 균열 단계를 올린다.
- 균열은 외형과 입자만 바꾸고 전투 수치는 바꾸지 않는다.

### 리치 왕 가속 오라

- 7초마다 반경 2.7칸 안의 다른 살아 있는 적을 3초간 20% 가속한다.
- 리치 왕 자신은 오라 대상에서 제외한다.
- 시전 시 보라색 룬 동심원을 400ms 동안 확장하고 대상 발밑에 작은 불꽃을 표시한다.
- 룬 애니메이션 반경은 실제 판정 반경과 일치한다.
- 리치 왕 HP는 보스용 보라색 바로 항상 표시한다.

나이트메어 6의 리치 왕은 HP 50%를 처음 통과할 때 2페이즈로 전환한다.

- 화면을 짧게 어둡게 하고 보라색 충격파를 한 번 재생한다.
- 오라 주기: 4.5초
- 가속량: 30%
- 지속시간: 3.5초
- 누출 피해: 12

2페이즈는 한 번만 시작하며 pause 중에는 진행되지 않는다.

## 엘리트

엘리트는 새 적 타입이나 별도 모델을 만들지 않고 기존 타입에 variant를 적용한다.

- HP 1.8배
- 속도 1.05배
- 처치 보상 1.5배
- 전투 점수 100점 추가
- 모델 10% 확대
- 붉은 룬 테두리와 5웨이브 출현 배너

| 스테이지 | 5웨이브 엘리트 |
|---|---|
| 달빛 늪 | 해골 기사 |
| 썩은 숲 | 흡혈 박쥐 |
| 잿빛 폐허 | 해골 기사 |
| 핏빛 협곡 | 그림자 슬라임 |
| 흑요석 광산 | 흑요석 골렘 |
| 심연의 성문 | 흑요석 골렘 |

엘리트 그림자 슬라임의 자식은 부모 최종 HP를 기준으로 35%를 받지만 엘리트 variant와 추가 점수는 상속하지 않는다.

## 공통 웨이브 골격

표의 숫자는 `그림자 슬라임/흡혈 박쥐/해골 기사/흑요석 골렘`의 기본 수다. 5웨이브 엘리트와 10웨이브 리치 왕은 표 밖에서 각각 정확히 1마리를 추가한다.

| 웨이브 | 슬라임 | 박쥐 | 해골 | 골렘 |
|---:|---:|---:|---:|---:|
| 1 | 10 | 0 | 0 | 0 |
| 2 | 8 | 6 | 0 | 0 |
| 3 | 6 | 8 | 3 | 0 |
| 4 | 8 | 4 | 6 | 0 |
| 5 | 0 | 8 | 6 | 0 |
| 6 | 6 | 6 | 8 | 2 |
| 7 | 10 | 8 | 6 | 3 |
| 8 | 6 | 8 | 9 | 4 |
| 9 | 8 | 6 | 10 | 5 |
| 10 | 6 | 8 | 10 | 5 |

기본 수가 0보다 클 때 다음 공식으로 스테이지별 수를 만든다.

```text
최종 수량 = round(기본 수량 × stage.countMultiplier × stage.typeWeight[type])
```

0인 그룹은 만들지 않으며, 보스와 엘리트에는 수량 공식을 적용하지 않는다. 생성 결과는 실행 중 무작위가 아니라 정적이고 재현 가능해야 한다.

분열한 자식까지 모두 처치한다는 가정의 예상 처치 수는 차례로 345, 347, 352, 463, 350, 449다. 결과 화면의 처치 수는 실제 개체 수를 표시하지만 점수는 적별 전투 점수를 사용해 분열 수량 때문에 부풀지 않게 한다.

| 5 | 흑요석 광산 | 1.47 | 1.08 | 0.88 | 1.16 |
| 6 | 심연의 성문 | 1.62 | 1.10 | 0.85 | 1.20 |

신규 적의 나이트메어 1 최종 수치는 현재 노멀 6의 대응 적과 비슷하게 잡는다. 예를 들어 10웨이브 리치 왕은 약 6,020 HP로 현재 노멀 6 미노타우르스 약 5,647 HP보다 조금 높다.

초기 수치에 대해 다음 목표로 결정적 전투 시뮬레이션을 실행한다.

- 나이트메어 1: 노멀 6을 안정적으로 깨는 배치가 비슷한 성공률을 낼 것
- 나이트메어 3: 한 가지 타워만 반복 배치하면 실패할 것
- 나이트메어 6: 화살·슬로우·덕배·후추 역할 조합이 필요할 것
- 빠른 적 또는 보스가 이론적으로 대응 불가능한 속도가 되지 않을 것

설계 재승인 없이 허용하는 자동 보정 범위는 표의 HP, 속도, 스폰 간격 및 수량 기준 ±10%다. 타워 가격·성능, 시작 골드와 창고 내구도는 이 보정 범위에서 제외한다.

## 직각 맵

모든 맵은 20×10 격자, 1칸 너비, 좌측 입구→우측 창고, 재방문 없는 직각 단일 경로다.

| 번호 | 이름 | 웨이포인트 | 이동 칸 | 배치 가능 칸 |
|---:|---|---|---:|---:|
| 1 | 달빛 늪 | `(0,7)→(4,7)→(4,2)→(10,2)→(10,6)→(15,6)→(15,4)→(19,4)` | 30 | 62 |
| 2 | 썩은 숲 | `(0,2)→(6,2)→(6,7)→(12,7)→(12,4)→(19,4)` | 27 | 56 |
| 3 | 잿빛 폐허 | `(0,8)→(5,8)→(5,4)→(14,4)→(14,2)→(19,2)` | 25 | 52 |
| 4 | 핏빛 협곡 | `(0,3)→(7,3)→(7,7)→(13,7)→(13,4)→(19,4)` | 26 | 54 |
| 5 | 흑요석 광산 | `(0,6)→(5,6)→(5,3)→(15,3)→(15,5)→(19,5)` | 24 | 50 |
| 6 | 심연의 성문 | `(0,4)→(8,4)→(8,6)→(13,6)→(13,4)→(19,4)` | 23 | 48 |

후반으로 갈수록 이동 거리와 배치 가능 칸을 대체로 줄인다. 핏빛 협곡은 이동 거리가 한 칸 늘지만 중앙 장거리 직선과 분열 슬라임 수량으로 압박을 만든다.

기존 `createStageMap`의 범위, 직각, 중복, 인접 배치 검증을 그대로 사용한다. 맵 렌더와 배치 판정이 다른 경로를 참조하지 않도록 둘 다 같은 `StageMap`을 사용한다.

## 다크 테마와 환경

| 스테이지 | 팔레트 및 분위기 |
|---|---|
| 달빛 늪 | 남색 물안개, 청록색 독기 |
| 썩은 숲 | 탁한 녹색 숲, 보라색 포자 |
| 잿빛 폐허 | 숯빛 바닥, 날리는 재와 작은 불씨 |
| 핏빛 협곡 | 적갈색 암반, 붉은 안개 |
| 흑요석 광산 | 검은 결정, 주황색 균열 |
| 심연의 성문 | 검보라색 바닥, 심연 입자와 비네트 |

Blender 공용 환경 키트는 바닥 타일, 무늬 없는 가로·세로 길, 네 방향 직각 코너, 경계석, 정면을 보는 저주받은 간식 상자로 구성한다. 입구 구조물은 만들지 않고 적이 생성될 때만 일시적인 포털 VFX를 재생한다.

환경 에셋은 단순 후보로 남기지 않고 `themeId`가 선택한 실제 맵 스프라이트 세트로 렌더러에 연결한다. fog, vignette, ash, ember 같은 가벼운 분위기 효과만 Canvas 합성 레이어로 처리한다. 길과 배치 가능 칸의 판독성을 해치는 불투명도는 허용하지 않는다.

`prefers-reduced-motion`에서는 화면 암전, 파티클 수와 반복 펄스를 줄이되 방패 잔여 여부, 오라 대상 및 보스 페이즈 같은 전투 정보는 정적인 색과 형태로 계속 구분한다.

## 점수와 별

노멀 점수 공식과 기존 7,000/10,000점 별 기준은 변경하지 않는다.

나이트메어는 적 수가 분열과 타입 가중치로 달라지므로 단순 `처치 수 × 25` 대신 전투 점수 합계를 사용한다.

```text
원점수 =
  완료 웨이브 × 500
  + 처치한 적의 전투 점수 합계
  + 남은 창고 내구도 × 100
  + 리치 왕 처치 시 1,500
  + 승리 시 max(0, 3,000 - floor(클리어 초 × 5))

최종 점수 = floor(원점수 × 1.5)
```

결과 화면에는 `나이트메어 보너스 ×1.5`를 별도 줄로 표시한다. 패배에는 시간 보너스, 별, 클리어 기록과 해금을 주지 않는다.

| 스테이지 | 2별 | 3별 |
|---|---:|---:|
| 달빛 늪 | 18,500 | 23,000 |
| 썩은 숲 | 19,000 | 23,500 |
| 잿빛 폐허 | 19,500 | 24,000 |
| 핏빛 협곡 | 20,500 | 25,000 |
| 흑요석 광산 | 20,500 | 25,000 |
| 심연의 성문 | 21,500 | 26,500 |

클리어는 최소 1별이다. `bestStars`는 해당 스테이지의 클리어 점수로만 올릴 수 있고 내려가지 않는다. 별 임계값도 초기 시뮬레이션에서 ±10% 안에서 보정할 수 있다.

## 결과 화면

기존 결과 제목은 유지한다.

- 승리: `간식 창고를 지켜줘서 고마워요`
- 패배: `간식 창고가 다 털려버렸어요`

나이트메어에서는 제목 아래에 모드와 스테이지명을 표시하고 다음 항목을 제공한다.

- 별, 최종 점수 및 새 최고 기록
- 웨이브, 실제 처치 수, 전투 점수
- 남은 내구도, 리치 왕 처리 여부
- 클리어 시간, 시간 보너스, 난이도 배율
- 해당 모드·스테이지 최고 점수와 최단 시간
- 다음 별까지 필요한 점수
- 선택 화면으로 돌아가는 명확한 주 버튼

나이트메어 6 최초 승리에서는 `심연의 수호자` 배지 획득을 결과 패널과 선택 화면에서 한 번 강조한다.

### 게이트 3: 최적화 및 런타임 통합

- 투명 배경과 타이트한 alpha bounds
- 모든 경로 방향에서 동일한 정면 프레임 사용
- 공용 VFX 오버레이로 중복 렌더 최소화
- 신규 최종 이미지 전체 목표 8MB 이하
- 누락 에셋은 로딩 실패로 게임을 중단하지 않되 검증 명령에서는 실패 처리

HTML Canvas는 Blender 모델 자체를 실시간으로 렌더하지 않는다. 승인된 Blender 장면을 투명 스프라이트와 스프라이트 시트로 렌더해 현재 Canvas 파이프라인에 통합한다.

## 렌더링 규칙

- 적은 경로 방향과 무관하게 항상 정면을 본다.
- 발 또는 몸체의 최저 alpha 픽셀이 타일 접점에 닿도록 anchor를 종류별로 검증한다.
- 방패, 오라와 엘리트 룬은 캐릭터 스프라이트 위의 공용 오버레이로 그린다.
- 적의 일반 HP는 피해 후 몇 초간만 표시하고 보스 HP는 항상 표시한다.
- 방패 애니메이션은 실제 잔여 방어 횟수와 동기화한다.
- 오라 원의 화면 반경은 월드 반경 2.7칸을 동일한 투영 함수로 변환한다.
- 데미지·분열·사망이 같은 tick에 겹치면 시뮬레이션 상태를 먼저 확정한 뒤 한 번만 시각 이벤트를 발행한다.
- 화면 밖 개체와 효과는 렌더하지 않고, 반복 파티클 수에 상한을 둔다.
- 나이트메어 시작 시 600ms 모드 타이틀을 표시하고 입력을 막지는 않는다.
- 10웨이브 리치 왕이 실제 생성되는 순간 보스 제목, 짧은 비네트와 보라색 충격파를 한 번만 재생한다.
