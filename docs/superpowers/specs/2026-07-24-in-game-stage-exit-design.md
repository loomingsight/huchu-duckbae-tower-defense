# 게임 중 스테이지 나가기 설계

## 배경

현재 플레이 중에는 일시정지, 속도 변경과 음소거만 조작할 수 있다. 다른
스테이지를 선택하거나 현재 도전을 포기하려면 승리 또는 패배 화면까지 진행해야
하므로, 사용자가 원할 때 스테이지 선택 화면으로 돌아갈 수 없다.

모바일 화면에서는 실수로 버튼을 누를 가능성이 있으므로 즉시 진행을 폐기하지
않고, 현재 진행이 저장되지 않는다는 확인 단계를 제공해야 한다.

## 목표

- 게임 진행 중 또는 일시정지 중에 스테이지 선택 화면으로 나갈 수 있다.
- 나가기 전에 현재 진행이 저장되지 않는다는 확인창을 표시한다.
- 확인창을 취소하면 나가기 전의 진행 또는 일시정지 상태를 정확히 복원한다.
- 중도 종료는 해금 상태, 최고 점수와 사용자 설정을 변경하지 않는다.
- 기존 스테이지 선택 화면과 포커스 관리 구조를 재사용한다.

## 범위에서 제외하는 항목

- 진행 중인 게임의 저장 및 이어하기
- 중도 종료 기록이나 별도 패널티 추가
- 스테이지 해금 및 점수 계산 규칙 변경
- 브라우저 새로고침 또는 탭 닫기 경고
- 새로운 이미지 및 오디오 에셋

## 사용자 흐름

### 확인창 열기

- 우측 상단 게임 컨트롤의 마지막 위치에 `나가기` 버튼을 추가한다.
- 버튼은 게임 진행 또는 일시정지 상태에서만 활성화한다.
- 게임 진행 중 버튼을 누르면 업데이트를 즉시 멈추고 확인창을 연다.
- 이미 일시정지 중이면 정지 상태를 유지한 채 확인창을 연다.
- 타워 배치 미리보기와 설치 타워 조회 상태는 확인창을 여는 동안 보존한다.

확인창 문구는 다음으로 고정한다.

- 제목: `게임을 그만둘까요?`
- 본문: `현재 스테이지 진행은 저장되지 않아요.`
- 안전 동작: `계속하기`
- 종료 동작: `스테이지 선택`

### 계속하기

- 확인창을 열기 전 게임이 진행 중이었다면 전투를 재개한다.
- 확인창을 열기 전 게임이 일시정지 중이었다면 일시정지 상태를 유지한다.
- 보존한 타워 배치 미리보기와 설치 타워 조회 상태를 그대로 복원한다.
- `Escape` 입력도 `계속하기`와 동일하게 처리한다.

### 스테이지 선택으로 이동

- 현재 게임의 몬스터, 타워, 투사체, 배치 미리보기, 조회 상태와 일시적인 전투
  효과를 폐기한다.
- 런타임을 `ready` 상태로 전환하고 전투 시뮬레이션 업데이트를 중단한다.
- 나가기 직전의 모드와 스테이지를 선택한 상태로 기존 스테이지 선택 화면을
  표시한다.
- 중도 종료는 승리, 패배 또는 최고 점수로 기록하지 않는다.
- 기존 해금 상태, 스테이지 기록, 음소거와 타워 버튼 위치 설정은 보존한다.
- 게임 시작 시 이미 기록되는 시도 횟수 외에 별도 종료 기록은 추가하지 않는다.

## 상태와 데이터 흐름

확인창은 게임 규칙의 `GamePhase`가 아니라 `GameApp`의 일시적인 UI 상태로
관리한다.

- `exitConfirmationOpen: boolean`
- `resumeAfterExitConfirmation: boolean`

진행 중 확인창을 열면 `resumeAfterExitConfirmation`을 `true`로 저장한 뒤 기존
일시정지 명령을 사용한다. 일시정지 중 열면 값을 `false`로 저장한다.

`계속하기`는 확인 UI를 닫은 뒤 `resumeAfterExitConfirmation`이 `true`인
경우에만 게임을 재개한다. 따라서 사용자가 직접 만든 일시정지 상태를 임의로
해제하지 않는다.

`GameRuntime`에는 `returnToStageSelect()` 명령을 추가한다. 이 명령은 다음
책임만 가진다.

- 진행 또는 일시정지 상태를 `ready`로 전환
- 현재 게임 객체를 같은 선택 스테이지의 초기 게임 객체로 교체
- 선택 중인 타워, 선택 셀과 조회 타워 ID 초기화
- 경과 시간과 고정 시간 누산기 초기화
- 변경된 상태를 한 번 렌더링

스테이지 선택 상태, 전투 시각 효과와 안내 메시지 같은 앱 수준 데이터는
`GameApp`에서 초기화한다. 새 게임은 기존 `startGame()` 흐름을 그대로 사용해
새 게임 상태를 생성한다. 애니메이션 프레임 예약은 기존 구조처럼 유지하되
`ready` 상태에서는 시뮬레이션 업데이트가 실행되지 않는다.

## 확인창 UI

기존 `stage-select-screen` DOM과 포커스 관리자를 확장한다.

- 일반 스테이지 선택 상태는 현재처럼 불투명한 전체 화면을 유지한다.
- 나가기 확인 상태에서는 `data-overlay-mode="confirm"`을 적용해 게임 화면이
  희미하게 보이는 반투명 스크림과 작은 확인 패널을 사용한다.
- 모드 탭, 스테이지 카드, 결과 패널과 배지는 확인 상태에서 숨긴다.
- 기존 주 동작 버튼을 `계속하기`에 사용하고 `스테이지 선택` 보조 버튼을
  추가한다.
- 스테이지 선택 화면에서는 보조 버튼을 숨겨 기존 레이아웃을 유지한다.
- 포커스 관리자는 같은 오버레이가 확인 모드에서 스테이지 선택 모드로 바뀌는
  경우도 새로운 모달 상태로 인식해 주 동작 버튼으로 포커스를 옮긴다.

`나가기` 버튼은 기존 게임 컨트롤과 동일한 최소 `44 × 44px` 터치 영역, 표면색과
포커스 표현을 사용한다. 세로 모바일 컨트롤에 추가돼도 맵을 과도하게 가리지
않도록 기존 `icon-control` 크기 안에서 `나가기` 텍스트를 표시한다.

## 접근성

- 나가기 버튼은 `aria-label="현재 게임을 그만두고 스테이지 선택으로 이동"`을
  제공한다.
- 확인창은 기존 `role="dialog"`와 `aria-modal="true"`를 유지한다.
- 확인창이 열리면 `계속하기` 버튼에 포커스를 둔다.
- 확인창 안에서 키보드 포커스를 순환시키고 배경 컨트롤에는 접근하지 못하게 한다.
- 확인창을 닫으면 나가기 버튼으로 포커스를 복원한다.
- `Escape`는 진행을 폐기하지 않고 확인창만 닫는다.
- 배경 스크림을 누르는 동작으로는 스테이지를 종료하지 않는다.

## 오디오와 렌더링

- 확인창이 열린 동안 런타임은 일시정지 상태이므로 전투 업데이트와 투사체 이동이
  멈춘다.
- BGM은 기존 일시정지 규칙과 동일하게 볼륨을 낮춘다.
- `계속하기`로 재개하면 기존 모드 또는 보스 BGM 흐름을 이어간다.
- 스테이지 선택으로 이동하면 활성 게임 세션이 종료되므로 전투 BGM을 중지한다.
- 확인창 뒤 캔버스에는 정지된 현재 전투 장면을 유지한다.

## 오류 및 경계 처리

- `loading`, `ready`, `victory`, `defeat` 상태에서는 나가기 버튼을 비활성화한다.
- 확인창이 이미 열린 상태에서 나가기 요청이 반복돼도 상태를 중복 변경하지 않는다.
- 확인창이 열린 동안 모든 배경 게임 조작을 포커스와 스크림으로 차단한다.
- 화면이 세로 방향 제한 상태로 바뀌면 방향 안내가 확인창보다 우선하고, 가로로
  돌아오면 기존 확인창 상태를 유지한다.
- 앱 종료 시 등록된 이벤트와 예약된 애니메이션 프레임을 기존 정리 흐름으로
  해제한다.

## 테스트와 검증

### 단위 및 DOM 테스트

- HUD에 나가기 버튼과 접근성 레이블이 생성된다.
- 버튼은 진행 또는 일시정지 상태에서만 활성화된다.
- 확인 모드가 제목, 본문, 두 동작 버튼을 표시하고 스테이지 선택 UI를 숨긴다.
- 확인창의 최초 포커스, 포커스 복원과 `Escape` 동작을 검증한다.
- 진행 중 `계속하기`는 전투를 재개하고, 일시정지 중 `계속하기`는 정지를 유지한다.
- `returnToStageSelect()`가 런타임 상태와 선택 정보를 초기화하고 업데이트를
  중단한다.
- 중도 종료가 스테이지 기록과 환경설정을 변경하지 않는다.

### 통합 검증

- `npm run check`로 Vitest, TypeScript 검사와 프로덕션 빌드를 실행한다.
- 빌드된 `dist/index.html`의 JS와 CSS 경로가
  `/huchu-duckbae-tower-defense/`로 시작하는지 확인한다.
- 모바일 가로 화면에서 다음 흐름을 스모크 테스트한다.
  - 진행 중 나가기 → 계속하기 → 전투 재개
  - 일시정지 중 나가기 → 계속하기 → 일시정지 유지
  - 나가기 → 스테이지 선택 → 기존 스테이지가 선택된 화면 표시
  - 배치 미리보기 중 확인 취소 시 상태 복원
  - 확인창과 방향 전환 안내의 우선순위

### 배포 검증

- `main` 푸시 후 GitHub Actions Pages 워크플로가 `success`인지 확인한다.
- 공개 게임 URL과 배포된 주요 JS 및 CSS 번들이 HTTP 200인지 확인한다.
- 배포 완료 전에는 기능이 공개됐다고 보고하지 않는다.

## 완료 조건

- 진행 또는 일시정지 중 언제든 확인창을 거쳐 스테이지 선택 화면으로 이동할 수
  있다.
- `계속하기`가 나가기 전 상태를 정확히 복원한다.
- 실수로 누르거나 `Escape`를 입력해도 진행이 폐기되지 않는다.
- 중도 종료가 해금 상태, 최고 점수와 설정을 변경하지 않는다.
- 모바일 맵과 기존 스테이지 선택, 일시정지 및 방향 안내 흐름이 회귀하지 않는다.
