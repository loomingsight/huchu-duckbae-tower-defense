# 나이트메어 혼합 타워 유도 밸런스 설계

- 작성일: 2026-07-24
- 대상 저장소: `huchu-defense-v2`
- 상태: 대화 설계 승인 완료, 문서 검토 후 구현
- 배포 대상: `main` → GitHub Pages

## 1. 배경

직전 조정에서 모든 나이트메어 스테이지의 첫 세 웨이브 그림자 슬라임 수를
낮추고 분열체 HP를 부모의 17%로 변경했다. 초반 진입 장벽은 완화됐지만,
현재는 화살 타워만 계속 추가해도 창고 피해 없이 쉽게 클리어할 수 있어
슬로우 타워와 고급 스플래시 타워를 선택할 이유가 약하다.

초반 슬라임 물량만 늘리면 가족당 11G인 보상 때문에 화살 타워 증설도
빨라진다. 따라서 수량, kill value와 중반 골렘 이동 압력을 함께 조정해
화살-only 전략은 불안정하게 만들고 슬로우 타워를 섞은 구성을 유리하게 한다.

## 2. 확정된 사용자 결정

| 항목 | 결정 |
| --- | --- |
| 목표 체감 | 화살-only도 숙련자는 1별 가능, 안정적인 2~3별에는 슬로우 타워 필요 |
| 초반 슬라임 | N1~N6 첫 3웨이브 물량을 소폭 증가 |
| 분열 | 본체 1마리에서 자식 2마리, 자식 HP 17% 유지 |
| 초반 kill value | 부모 배율 2.0에서 1.6으로 감소 |
| 흑요석 골렘 | 기본 속도 0.44에서 0.52로 증가 |
| 경제·점수 | 물량 증가 전과 비교해 초반 총량을 비슷하게 유지 |
| 검증 | 집중 단위 테스트, 전체 단위 테스트, 타입 검사, 프로덕션 빌드 |
| 제외 | 전체 E2E, 맵·UI·에셋·애니메이션 변경 |

## 3. 목표

1. 첫 세 웨이브의 단일 대상 화력 요구량을 현재보다 완만하게 높인다.
2. 늘어난 슬라임이 추가 화살 타워 구매 자금으로 그대로 전환되지 않게 한다.
3. 6웨이브부터 등장하는 흑요석 골렘이 슬로우 타워의 명확한 사용처가 되게
   한다.
4. 화살-only 전략을 완전히 금지하지 않고 숙련된 배치의 1별 선택지로 남긴다.
5. 다른 적, 타워 가격과 기존 분열 특성을 건드리지 않고 최소 수치 변경으로
   조정한다.

## 4. 비목표

- 화살 타워의 공격력, 공격 간격, 사정거리와 가격은 변경하지 않는다.
- 슬로우 타워의 가격, 사정거리와 감속 배율 0.62는 변경하지 않는다.
- 덕배·후추 타워 수치는 변경하지 않는다.
- 그림자 슬라임 본체·자식 HP, 이동 속도, 자식 수와 재분열 규칙은 변경하지
  않는다.
- 박쥐, 해골 기사, 리치 왕과 노멀 적의 수치는 변경하지 않는다.
- 시작 골드, 창고 HP, 스테이지 HP·속도·수량·간격 배율과 별점 기준은
  변경하지 않는다.
- 실제 플레이 결과 없이 화살-only 실패를 강제하는 추가 저항 특성은 만들지
  않는다.

## 5. 초반 그림자 슬라임 수량

`src/game/waves/nightmareWaves.ts`의 첫 세 그림자 슬라임 베이스 수량을
`6/5/4`에서 `7/6/5`로 변경한다. 기존 `TYPE_WEIGHTS`와 스테이지
`countMultiplier`를 적용한 최종 수량은 다음과 같다.

| 스테이지 | 현재 1~3웨이브 | 변경 후 1~3웨이브 | 부모 총수 |
| --- | ---: | ---: | ---: |
| N1 | 6 / 5 / 4 | 7 / 6 / 5 | 15 → 18 |
| N2 | 5 / 5 / 4 | 6 / 5 / 5 | 14 → 16 |
| N3 | 5 / 4 / 3 | 6 / 5 / 4 | 12 → 15 |
| N4 | 8 / 7 / 5 | 10 / 8 / 7 | 20 → 25 |
| N5 | 5 / 4 / 3 | 6 / 5 / 4 | 12 → 15 |
| N6 | 7 / 6 / 5 | 8 / 7 / 6 | 18 → 21 |

4~10웨이브 수량, 다른 적 그룹, 스폰 간격, 엘리트와 보스는 변경하지 않는다.

## 6. 초반 골드와 전투 점수

첫 세 그림자 슬라임 부모 그룹의 `killValueMultiplier`를 2.0에서 1.6으로
낮춘다. 부모 생성 시 기존 반올림 규칙을 적용하면 다음 가족 가치가 된다.

| 항목 | 현재 | 변경 후 |
| --- | ---: | ---: |
| 부모 골드 | `round(4 × 0.85 × 2.0) = 7G` | `round(4 × 0.85 × 1.6) = 5G` |
| 자식 골드 | 2G × 2 | 2G × 2 |
| 가족 골드 | 11G | 9G |
| 부모 전투 점수 | 15 × 2.0 = 30 | 15 × 1.6 = 24 |
| 자식 전투 점수 | 5 × 2 | 5 × 2 |
| 가족 전투 점수 | 40 | 34 |

스테이지별 첫 세 웨이브의 그림자 슬라임 총 경제와 점수는 다음과 같다.

| 스테이지 | 골드 현재 → 변경 | 편차 | 점수 현재 → 변경 | 편차 |
| --- | ---: | ---: | ---: | ---: |
| N1 | 165G → 162G | -2% | 600 → 612 | +2% |
| N2 | 154G → 144G | -6% | 560 → 544 | -3% |
| N3 | 132G → 135G | +2% | 480 → 510 | +6% |
| N4 | 220G → 225G | +2% | 800 → 850 | +6% |
| N5 | 132G → 135G | +2% | 480 → 510 | +6% |
| N6 | 198G → 189G | -5% | 720 → 714 | -1% |

초반 총 골드는 현재 대비 -6%~+2%, 전투 점수는 -3%~+6% 범위다. 기존
타워 성장과 별점 기준을 크게 바꾸지 않으므로 시작 골드와 점수 임계값은
유지한다.

## 7. 흑요석 골렘 속도

`ENEMY_CATALOG.obsidianGolem.speed`를 0.44에서 0.52로 높인다. HP 620,
보상 28G, 누수 피해 3과 나머지 속성은 유지한다.

| 스테이지 | 스테이지 배율 적용 속도 | 슬로우 적용 속도 | 완주 시간 현재 → 변경 |
| --- | ---: | ---: | ---: |
| N1 | 0.5200 | 0.3224 | 68.2초 → 57.7초 |
| N2 | 0.5200 | 0.3224 | 61.4초 → 51.9초 |
| N3 | 0.5304 | 0.3288 | 55.7초 → 47.1초 |
| N4 | 0.5356 | 0.3321 | 57.4초 → 48.5초 |
| N5 | 0.5460 | 0.3385 | 51.9초 → 44.0초 |
| N6 | 0.5564 | 0.3450 | 48.9초 → 41.3초 |

완주 시간은 각 스테이지 경로 길이를 기본 이동 속도로 나눈 정적 비교값이며,
리치 오라와 실제 슬로우 타워 사정거리 체류 시간은 포함하지 않는다. 이 값은
게임 결과를 보장하는 시뮬레이션이 아니라 속도 변화의 회귀 계약으로 사용한다.

## 8. 구현 구조

새 런타임 타입이나 분기 로직은 추가하지 않는다.

- `src/game/waves/nightmareWaves.ts`
  - 첫 세 베이스 수량 `7/6/5`
  - 해당 그룹 `killValueMultiplier: 1.6`
- `src/game/enemies/enemyCatalog.ts`
  - `obsidianGolem.speed: 0.52`
- 기존 `WaveGroup.killValueMultiplier` 유효성 검사와 `spawnEnemy` 계산을
  그대로 재사용한다.
- 기존 `updateEnemies`의 분열체 HP 17%, 보상·점수 override를 유지한다.
- 기존 `updateSlow`의 감속 배율 적용 순서를 유지한다.

유효하지 않은 kill value는 현재처럼 `isValidWaveGroup`에서 거부하고,
직접 생성 호출의 유효하지 않은 값은 1로 정규화한다.

## 9. 테스트 전략

### 9.1 웨이브·경제·점수

- N1~N6 첫 세 그림자 슬라임 최종 수량을 승인 표와 대조한다.
- 첫 세 그룹의 `killValueMultiplier`가 모두 1.6인지 검증한다.
- 4~10웨이브의 그림자 슬라임 수량과 kill value가 현재와 같은지 검증한다.
- 초반 부모가 5G·24점, 가족 전체가 9G·34점을 주는지 검증한다.
- 후반 가족은 기존 7G·25점을 유지하는지 검증한다.
- 스테이지별 초반 총 골드·점수가 승인 편차 범위 안인지 검증한다.

### 9.2 골렘·슬로우

- 흑요석 골렘 기본 속도가 0.52인지 검증한다.
- N1~N6의 스테이지 배율 적용 속도를 표와 대조한다.
- 슬로우 적용 시 각 속도가 `기본 × 스테이지 배율 × 0.62`인지 검증한다.
- 골렘 HP·보상·누수 피해와 다른 적 속도가 바뀌지 않았는지 검증한다.

### 9.3 통합 검증

- 집중 Vitest
- `npm run check`
- `dist/index.html`의 JS/CSS 경로가
  `/huchu-duckbae-tower-defense/`로 시작하는지 확인
- 전체 E2E는 밸런스 수치 변경 정책에 따라 실행하지 않음
- 화살-only와 혼합 구성의 별점 체감은 배포 후 실제 플레이 후속 조정 항목으로
  백로그에 기록

## 11. 완료 기준

- N1~N6 첫 세 웨이브의 그림자 슬라임 수량이 승인 표와 일치한다.
- 초반 가족 가치가 9G·34점이고 후반 가족 가치는 유지된다.
- 자식 HP 17%와 `1 → 2` 분열이 유지된다.
- 흑요석 골렘 기본 속도는 0.52이고 슬로우 적용 계산이 정확하다.
- 다른 적, 타워 가격, 시작 골드와 별점 기준은 변경되지 않는다.
- 전체 단위 테스트, 타입 검사와 프로덕션 빌드가 통과한다.
- GitHub Pages 배포와 공개 리소스 응답이 검증된다.
