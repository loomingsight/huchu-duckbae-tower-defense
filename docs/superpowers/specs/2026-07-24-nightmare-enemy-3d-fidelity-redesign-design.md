# 나이트메어 적 3D 정교화 설계

## 상태

- 사용자 승인: 2026-07-24
- 선택안: A — 마인크래프트형 각진 형태를 유지하면서 2D 승인본의 얼굴 비율·장비·문양·재질을 입체적으로 세분화
- 대상: 그림자 슬라임, 흡혈 박쥐, 해골 기사, 흑요석 골렘, 리치 왕
- 기준 도안: `assets/concepts/nightmare-v1/nightmare-enemy-lineup-v3.png`
- 실행 방식: 승인된 단일 에이전트 방식
- 검증 정책: E2E 제외, Vitest·TypeScript·Vite production build·에셋 계약 검사·모바일 렌더 수동 검수

## 문제

현재 `nightmare-v1` 3D 후보는 적의 종류와 기본 실루엣은 구분되지만 큰 기본 도형 몇 개로만 구성되어 있다. 2D 승인본에 있는 얼굴 구조, 갑옷 층, 장비 외곽선, 균열, 왕관과 로브 같은 식별 특징이 대부분 사라져 128px에서도 개성이 약하다.

이번 작업에서는 폴리곤 수 자체를 무작정 늘리지 않는다. 모바일 실제 크기에서 읽히는 중간·큰 크기의 형태를 여러 층으로 나누고, 명도·재질·발광 대비를 사용해 승인된 2D 도안과 같은 캐릭터로 인식되게 만든다.

## 범위

### 포함

- 적 5종의 Blender 모델과 정면 동작 시트 전면 재작업
- 얼굴, 장비, 문양, 재질을 나타내는 의미 기반 세부 부품 계약
- master 256px 및 mobile 128px 투명 스프라이트 렌더
- 신규 적 동작 시트의 런타임 연결
- 기존 나이트메어 적 fallback을 로딩 실패 시에만 유지
- 적 5종 전용 desktop/mobile 승인 보드

### 제외

- 나이트메어 특성 VFX 재디자인
- 나이트메어 6개 맵 키트 재디자인
- 노멀 적, 타워, 투사체 에셋 변경
- 실시간 WebGL 3D 모델 로딩
- 밸런스, 웨이브, 점수, 저장 데이터 변경
- Playwright 및 기타 E2E 실행
- 별도 사용자 요청 없는 원격 push와 GitHub Pages 배포

## 선택한 제작 방식

절차형 Blender 생성기를 유지하되, 캐릭터마다 큰 덩어리·중간 장비·얼굴 강조·발광 포인트의 네 층으로 나눈다.

1. **큰 덩어리:** 128px에서 먼저 읽히는 머리, 몸통, 날개, 어깨와 로브
2. **중간 장비:** 방패 테두리, 검 손잡이, 골렘 갑옷판, 리치 왕관과 견갑
3. **얼굴 강조:** 눈구멍, 눈, 코, 턱, 이빨, 볼과 눈썹
4. **발광 포인트:** 청록 눈, 보라 보석, 주황 균열과 핵

세부 부품은 얇은 사진 텍스처로 붙이지 않고 실제 mesh 또는 curve로 만든다. 따라서 보간과 투명 배경에서도 외곽선이 유지되고, 동작 프레임에서 부품이 함께 움직인다.

### 대안과 제외 이유

- 둥근 sculpt 중심 모델: 2D와 비슷하게 만들 수 있으나 기존 각진 게임 스타일과 달라지고 수정 자동화가 어렵다.
- 단순 모델 + 평면 텍스처: 제작은 빠르지만 회전·조명·동작에서 입체감이 약하고 사용자가 지적한 “단순함”을 해결하지 못한다.

## 버전과 보존 정책

- 기존 거절 후보는 `assets/renders/nightmare-v1/`과 `assets/blender/nightmare-enemies-v1.blend`에 그대로 보존한다.
- 정교화 모델은 `assets/blender/nightmare-enemies-v2.blend`에 저장한다.
- 정교화 렌더는 `assets/renders/nightmare-v2/{master,mobile}/motion/`에 저장한다.
- VFX와 맵은 기존 `nightmare-v1` 결과를 재사용한다.
- 혼합 에셋 계약은 motion만 v2 root를, VFX와 map은 v1 root를 가리킨다.
- 런타임은 정교화 motion v2만 연결한다.

## 캐릭터별 시각 계약

### 그림자 슬라임

- 진보라색 반투명 큐브형 몸체와 계단형 윗면을 유지한다.
- 한 개의 매끈한 상자가 아니라 외곽 결정 블록, 내부 핵, 윗면 판, 작은 부유 큐브로 깊이를 만든다.
- 청록색 눈은 얼굴에서 가장 밝고 큰 요소로 유지하고 작은 입과 볼 하이라이트를 분리한다.
- 분열 자식에서도 눈과 외곽 실루엣이 읽혀야 한다.

### 흡혈 박쥐

- 머리보다 넓은 양쪽 날개와 큰 귀를 최우선 실루엣으로 유지한다.
- 날개는 외곽 골격, 3개 이상의 막 패널, 손가락형 날개뼈와 끝 갈고리로 나눈다.
- 바깥 귀·안쪽 귀, 눈두덩, 주둥이, 코, 두 송곳니, 발톱을 구분한다.
- 모든 동작 프레임은 정면 얼굴을 유지하고 날개만 크게 접혔다 펼쳐진다.

### 해골 기사

- 큰 두개골과 작은 몸체의 균형, 정면 왼쪽 방패와 오른쪽 짧은 검 구도를 유지한다.
- 두개골은 이마, 관자, 광대, 턱, 눈구멍, 코구멍과 개별 앞니로 나눈다.
- 목 스카프, 갈비뼈, 척추, 관절과 장화형 발을 구분한다.
- 방패는 바깥 테두리, 안쪽 판, 리벳, 중앙 보라 보석을 갖고 얼굴을 가리지 않는다.
- 검은 칼날, 날, 가드, 손잡이와 끝장식을 분리한다.

### 흑요석 골렘

- 1타일 안에 들어오는 가장 무거운 체급과 넓은 어깨·큰 주먹을 유지한다.
- 머리, 가슴, 배, 어깨, 위팔, 아래팔, 주먹, 허벅지와 발을 서로 다른 암석판으로 겹친다.
- 눈썹판과 턱판으로 얼굴을 만들고 주황 눈·가슴 핵을 강조한다.
- 균열은 단순한 세로 막대가 아니라 가슴, 어깨와 팔을 따라 꺾이는 여러 조각으로 만든다.

### 리치 왕

- 다리가 바닥에 닿지 않는 부유형 작은 몸체와 큰 해골 얼굴을 유지한다.
- 두개골은 해골 기사와 같은 수준의 눈구멍·코·턱·앞니를 갖되 보라 눈으로 구분한다.
- 왕관은 중앙 대형 첨탑과 좌우 첨탑, 보라 보석, 금속 테두리로 구성한다.
- 후드, 높은 칼라, 견갑, 가슴 보석, 허리띠와 여러 갈래의 짧은 로브를 겹친다.
- 양손은 손바닥과 손가락 마디가 보이는 주문 시전 포즈를 유지한다.
- 캐릭터 옆의 작은 보라 혼불은 투사체가 아니라 리치 왕 고유 실루엣 장식으로만 사용한다.

## 동작 계약

| 대상 | 프레임 | 목표 동작 | 정면 유지 |
|---|---:|---|---|
| 그림자 슬라임 | 6 | 눌림 → 상승 → 착지, 외곽 블록 지연 | 예 |
| 흡혈 박쥐 | 8 | 넓은 날개 펼침 → 접힘, 몸통의 느린 부유 | 예 |
| 해골 기사 | 6 | 좌우 팔·다리 교차 보행, 방패와 검의 작은 반동 | 예 |
| 흑요석 골렘 | 6 | 무거운 보행, 어깨·주먹의 낮은 반동 | 예 |
| 리치 왕 | 8 | 느린 상하 부유, 왕관·로브·손의 위상차 | 예 |

프레임 수와 게임 속도는 기존 계약을 유지한다. 모델 디테일을 이유로 시뮬레이션 속도나 충돌 판정을 바꾸지 않는다.

## 런타임 연결

`spriteManifest.ts`는 다섯 v2 motion sheet의 URL, 프레임 수와 FPS를 정의한다. `assetLoader.ts`는 노멀 동작 두 종과 신규 동작 다섯 종을 모두 로드한다. `drawEntities.ts`는 적 타입에 motion 정의가 있으면 해당 sheet를 사용하고, 이미지 로딩에 실패한 경우에만 기존 Canvas fallback을 그린다.

모든 신규 적은 이동 방향과 무관하게 같은 정면 motion sheet를 사용한다. 지상형 적은 타일 앞쪽 anchor에 붙이고, 박쥐와 리치 왕의 부유는 sheet 내부 동작으로 표현한다. 별도의 Canvas bob은 중복 적용하지 않는다.

## 자동 검증

- 적 5종 ID, 프레임 수, v2 root와 runtime URL이 정확하다.
- 캐릭터별 필수 세부 역할 이름과 최소 부품 수가 계약에 존재한다.
- 각 master sheet는 `256 × frames` × `256`, mobile sheet는 `128 × frames` × `128`이다.
- 모든 PNG 네 모서리 alpha는 0이다.
- 모바일 나이트메어 전체 후보는 8MB 이하를 유지한다.
- 신규 동작 이미지 로딩 실패는 해당 적 하나에만 fallback을 적용한다.
- 신규 적은 motion frame을 시간에 따라 전환하고 정적 방향 이미지를 사용하지 않는다.
- E2E는 실행하지 않는다.

## 수동 검수

- desktop 승인 보드에서 2D 도안과 정면 실루엣·색·장비 구도를 나란히 확인한다.
- mobile 승인 보드에서 128px 기준으로 눈, 얼굴, 대표 장비와 발광 포인트가 분리되는지 확인한다.
- 각 적의 첫·중간·마지막 프레임에서 부품이 떨어지거나 잘리지 않는지 확인한다.
- 지상형 셋은 바닥선이 일치하고 박쥐·리치 왕만 의도적으로 부유하는지 확인한다.
- 승인 보드는 구현 증거이며, 사용자에게 별도 재질문 없이 로컬 구현을 완료하되 사용자 최종 시각 승인 전에는 “최종 에셋 승인”으로 기록하지 않는다.
