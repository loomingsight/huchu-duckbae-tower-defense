# Slow Pulse and Economy Balance Design

## Goal

슬로우 타워가 설치 순간뿐 아니라 설치 후에도 3초 간격으로 보라색 파동을 반복하도록 만들고, 덕배·후추를 초반부터 쉽게 도배할 수 없도록 스테이지 1의 골드 경제를 중간 난이도로 조정한다.

## Scope

이번 배치는 다음 두 동작만 변경한다.

1. 슬로우 타워별 설치 시각을 기준으로 즉시 1회, 이후 게임 시간 3초마다 보라색 파동 표시
2. 시작 골드, 덕배·후추 가격, 몬스터 처치 보상 조정

슬로우·화살 타워 가격, 모든 타워의 공격력·사거리·공격 주기, 슬로우 배율, 몬스터 체력·속도·누출 피해, 웨이브 구성은 변경하지 않는다. 파동은 기존 Canvas 동심원 표현을 재사용하므로 새 이미지나 Blender 렌더는 추가하지 않는다.

## Slow Tower Pulse

### Timing contract

- 설치 직후 `0.0~0.6초` 동안 기존 보라색 확장 링을 표시한다.
- 같은 타워의 설치 시각으로부터 `3.0`, `6.0`, `9.0`초 시점마다 다시 `0.6초` 동안 표시한다.
- 주기는 실제 벽시계가 아니라 게임의 `elapsedSeconds`를 사용한다.
- 일시정지와 세로 화면 차단 중에는 게임 시간이 멈추므로 파동 주기도 멈춘다.
- 2배속에서는 게임 시간이 2배로 흐르므로 실제 시간 기준 약 1.5초마다 보인다.
- 슬로우 타워가 여러 개면 각각 자신의 설치 시각을 기준으로 독립적으로 반복한다.

### State model

`GameTower`에 `placedAtSeconds: number`를 추가한다. `placeTower`는 설치가 성공할 때 현재 `GameState.elapsedSeconds`의 유효한 0 이상 값을 저장한다. 이 값은 전투 수치가 아니라 렌더 애니메이션 기준점이며 재시작하면 새 게임 상태와 함께 초기화된다.

`effects.ts`에 다음 계약을 둔다.

- `SLOW_PULSE_INTERVAL_SECONDS = 3`
- `SLOW_PULSE_DURATION_SECONDS = 0.6`
- `slowPulseEffects(towers, elapsedSeconds): RuntimeEffect[]`

함수는 슬로우 타워만 필터링하고 `elapsedSeconds - placedAtSeconds`의 3초 주기 나머지를 effect age로 계산한다. age가 `0.6` 미만인 타워만 기존 `slow-pulse` 효과로 반환한다. 입력 상태와 타워를 변경하지 않는 순수 함수로 구현한다.

`GameApp.render`는 일반 타격 효과와 함께 `slowPulseEffects` 결과를 renderer에 전달한다. 설치 확정 핸들러에서 수동으로 `createSlowPulse`를 한 번 추가하던 코드는 제거하여 설치 프레임의 중복 링을 방지한다. 기존 ground-effect 렌더 순서를 유지해 파동은 타워와 몬스터 아래에 그린다.

## Economy Balance

### Starting budget and tower cost

| 항목 | 현재 | 변경 |
|---|---:|---:|
| 시작 골드 | 450G | 320G |
| 슬로우 타워 | 80G | 80G |
| 화살 타워 | 100G | 100G |
| 덕배 | 250G | 420G |
| 후추 | 300G | 560G |

시작 시에는 화살 타워 3개 또는 슬로우 1개와 화살 2개처럼 기본 조합을 만들 수 있지만 덕배·후추는 즉시 건설할 수 없다.

### Enemy reward

| 몬스터 | 현재 | 변경 |
|---|---:|---:|
| 슬라임 | 10G | 8G |
| 빠른 요정 | 14G | 10G |
| 녹색 오크 | 20G | 15G |
| 스톤 골렘 | 38G | 28G |
| 미노타우르스 | 200G | 150G |

모든 적을 처치할 때 받을 수 있는 총 보상은 `3,436G`에서 `2,562G`로 약 25% 감소한다. 시작 골드를 포함한 이론상 총예산은 `3,886G`에서 `2,882G`로 감소한다.

누출 없이 진행하면 누적 보유 가능 골드는 1웨이브 종료 시 `384G`, 2웨이브 종료 시 `480G`, 3웨이브 종료 시 `620G`다. 따라서 다른 지출이 없다는 상한 기준으로 덕배는 2웨이브, 후추는 3웨이브부터 열리며 실제 플레이에서는 기본 타워 지출 때문에 더 늦어진다.

## Architecture Changes

- `createGame.ts`: `INITIAL_GOLD = 320` 상수와 `GameTower.placedAtSeconds`
- `placeTower.ts`: 성공한 설치에 현재 게임 시간 기록
- `towerCatalog.ts`: 덕배·후추 비용 변경
- `enemyCatalog.ts`: 5종 처치 보상 변경
- `effects.ts`: 타워별 반복 파동을 계산하는 순수 함수와 주기 상수
- `GameApp.ts`: 반복 파동 결과를 매 프레임 합성하고 설치 시 일회성 수동 effect 제거

새 런타임 의존성, 저장 데이터 마이그레이션, 에셋 파일은 추가하지 않는다.

## Edge Cases

- 유효하지 않은 `elapsedSeconds`나 `placedAtSeconds`는 0으로 정규화해 Canvas에 NaN이 전달되지 않게 한다.
- 현재 시간이 설치 시각보다 작으면 경과 시간을 0으로 처리한다.
- 일반 공격 타워에는 파동을 만들지 않는다.
- 파동 effect 배열은 새로운 객체만 반환하고 게임 상태를 변경하지 않는다.
- 골드가 새 가격과 정확히 같으면 기존 정책대로 버튼과 설치를 허용한다.
- 처치 보상은 기존 `rewarded` 플래그를 유지하여 적 한 마리당 한 번만 지급한다.

## Testing Strategy

TDD로 각 변경 전 실패를 확인한다.

1. `createGame()`이 `320G`로 시작하고 새 덕배·후추 가격 및 몬스터 보상 표와 일치하는 테스트
2. 설치 시간이 `GameState.elapsedSeconds`와 일치하고 실패한 설치에는 타워가 생기지 않는 테스트
3. 파동이 설치 직후, `3.0초`, `6.0초`에 나타나고 각 주기의 `0.6초`부터 사라지는 경계 테스트
4. 서로 다른 시각에 설치한 두 슬로우 타워가 독립 phase를 가지며 일반 타워는 제외되는 테스트
5. renderer가 생성된 파동을 타워 아래의 보라색 projected ring으로 그리는 기존 렌더 계약 회귀 테스트
6. HUD가 새 덕배·후추 가격과 새 시작 골드를 표시하고 부족한 버튼을 비활성화하는 테스트
7. 844×390 E2E에서 시작 직후 고급 타워가 비활성이고 기본 타워 조합으로 시작한 뒤 덕배·후추를 단계적으로 추가해 승리 가능한지 검증
8. 전체 `npm run check`, 모바일 E2E, 프로덕션 빌드 경로 및 공개 배포 HTTP 200 검증

## Acceptance Criteria

- 슬로우 타워마다 설치 즉시 및 게임 시간 3초 간격으로 기존 보라색 파동이 반복된다.
- 일시정지 중에는 파동 phase가 진행되지 않고 재시작 시 이전 타워 schedule이 남지 않는다.
- 시작 골드는 320G이며 덕배 420G, 후추 560G다.
- 몬스터 보상은 8/10/15/28/150G로 적용되고 한 번만 지급된다.
- 시작 직후 덕배와 후추 버튼은 비활성이다.
- 기본 타워 조합으로 스테이지를 시작할 수 있다.
- 단위 테스트, 타입 검사, 프로덕션 빌드와 배포 후 공개 리소스 검증이 통과한다.
- 모바일 E2E와 실제 승리 난이도 검증은 사용자 결정에 따라 후속 플레이 피드백으로 진행한다.
