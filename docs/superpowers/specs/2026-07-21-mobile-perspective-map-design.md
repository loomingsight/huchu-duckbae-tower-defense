# 모바일 원근 맵 재설계

## 상태

- 사용자 승인: 2026-07-21
- 선택안: B 원근 확대 시점
- 구현 대상: HTML Canvas 모바일 가로 화면

## 목표

1. 입구를 화면 왼쪽, 간식 창고를 오른쪽에 배치해 몬스터 진행이 좌→우로 읽히게 한다.
2. 위쪽 행은 작고 아래쪽 행은 크게 보이는 원근감을 적용한다.
3. 844×390 모바일 가로 화면에서 맵과 전투 유닛을 현재보다 크게 보여준다.
4. 길이 아닌 타일을 녹색으로, 길을 무늬 없는 밝은 모래색으로 표시한다.
5. 몬스터와 후추·덕배는 이동 및 공격 방향과 무관하게 항상 카메라 정면을 보게 한다.
6. 화면 좌표와 터치 역변환이 같은 투영 모델을 사용하도록 유지한다.

## 범위에서 제외하는 사항

- 20×10 그리드, 경로 웨이포인트, 웨이브 구성 및 전투 밸런스 변경
- 맵 스크롤, 드래그 카메라, 확대·축소 조작
- 신규 캐릭터 방향 렌더 생성
- 타워 가격, 사거리, 공격력 및 배치 규칙 변경
- 저장 데이터 형식 변경

## 맵 투영

### 월드 좌표 유지

게임 시뮬레이션은 기존 `col`, `row` 좌표와 20×10 그리드를 그대로 사용한다. 경로도 `{ col: 0, row: 2 }`에서 시작해 `{ col: 19, row: 3 }`에서 끝나는 현재 데이터를 유지한다. 화면 투영만 변경하므로 시뮬레이션, 타게팅, 사거리 계산에는 영향을 주지 않는다.

### 사다리꼴 원근 투영

행 깊이를 `depth = row / GRID_HEIGHT`로 정규화하고, 가로 배율을 위쪽 0.75에서 아래쪽 1.10까지 선형 보간한다. 여기서 셀 꼭짓점의 `row`는 보드 위쪽 경계의 `0`부터 아래쪽 경계의 `GRID_HEIGHT`까지이며, 엔티티는 셀 내부의 소수 좌표를 그대로 사용한다.

```text
depthScale(row) = lerp(0.75, 1.10, clamp(row / GRID_HEIGHT, 0, 1))
screenX = mapCenterX + (col - GRID_WIDTH / 2) * baseCellWidth * depthScale(row)
screenY = mapTop + row * rowStep
```

셀의 네 꼭짓점을 각각 투영해 위쪽이 좁고 아래쪽이 넓은 사다리꼴 타일을 만든다. `col`이 화면 가로축의 주성분이므로 입구는 항상 왼쪽, 창고는 항상 오른쪽에 놓인다. `row` 변화는 경로의 상하 굴곡으로 표현된다.

### 화면 점유율

- 맵 가로 폭: 게임 캔버스의 약 90~94%
- 맵 세로 높이: 게임 캔버스의 약 72~80%
- 위쪽 여백: HUD와 겹치지 않는 최소 여백
- 전체 20×10 맵과 입구·창고는 잘리지 않고 항상 표시
- 세부 비율은 844×390 기준 시각 테스트에서 확정

## 렌더링 구조

### 공통 투영 모듈

맵, 엔티티, 사거리, 투사체, 폭발 효과 및 입력이 하나의 투영 API를 공유한다.

```text
projectWorldPoint(layout, world) -> screen point
projectCellPolygon(layout, cell) -> four screen points
perspectiveScaleAt(layout, row) -> depth scale
unprojectScreenPoint(layout, screen) -> world point or null
```

기존 `worldToScreen` 호출부는 공통 투영 함수로 연결하고, 입력 코드는 독립적인 수식을 중복하지 않는다.

### 타일과 색상

- 비길 타일 기본색: 녹색 `#4f8c65`
- 인접 행의 미세한 변주: `#5d9a70`
- 길 기본색: 밝은 모래색 `#e4c99f`
- 그리드 선: 반투명 짙은 녹색
- 길 표면에는 반복 무늬를 넣지 않는다.
- 맵 아래쪽 외곽에 얇은 측면을 그려 3D 보드 두께는 유지한다.
- 입구와 간식 창고는 기존 3D 에셋을 원근 배율에 맞춰 배치한다.

### 유닛 크기와 접지

- 캐릭터 기준 표시 크기를 현재의 1.25배로 설정한다.
- 이 기준 크기에 맵과 동일한 0.75~1.10 깊이 배율을 한 번만 곱해, 현재 크기 대비 위쪽 약 0.94배부터 아래쪽 최대 약 1.38배까지 표시한다.
- 타워와 몬스터의 발·받침대 접점은 투영된 셀의 앞쪽 가장자리에 맞춘다.
- HP 바, 투사체, 폭발 효과도 같은 깊이 배율을 사용한다.
- 화면 세로 위치를 기준으로 엔티티를 정렬해 앞쪽 유닛이 뒤쪽 유닛 위에 그려지게 한다.

## 캐릭터 방향

### 정면 고정 대상

- 슬라임
- 요정
- 오크
- 스톤 골렘
- 미노타우르스
- 후추
- 덕배

몬스터는 경로 진행 방향과 관계없이 기존 리소스 키가 `se`인 카메라 정면 스프라이트를 사용한다. 이 문서에서 `se`는 파일·리소스 식별자일 뿐 화면상 남동 방향을 의미하지 않는다. 오크 걷기와 요정 날갯짓은 기존 정면 모션 시트를 모든 경로 구간에서 재생한다. 슬라임의 바운스 등 코드 기반 동작은 유지한다.

### 방향 추적 유지 대상

- 화살 타워의 조준 방향
- 화살 투사체
- 기타 타워의 투사체 이동 방향

슬로우 타워는 방향 개념이 없으므로 현재 형태를 유지한다.

## 입력 역변환

`screenY`에서 먼저 행 깊이를 구하고, 해당 깊이의 가로 배율로 `screenX`를 역산한다.

```text
row = (screenY - mapTop) / rowStep
scale = depthScale(row)
col = GRID_WIDTH / 2 + (screenX - mapCenterX) / (baseCellWidth * scale)
```

역변환 결과가 유한하지 않거나 그리드 밖이면 `null`을 반환한다. 셀 선택은 역산한 좌표의 정수 셀뿐 아니라 실제 투영된 셀 다각형 내부인지도 확인해 사다리꼴 바깥의 잘못된 선택을 막는다.

## 데이터 흐름

```text
GameState world coordinates
  -> shared perspective projection
  -> map, towers, enemies, projectiles, effects

Pointer client coordinates
  -> canvas coordinates
  -> shared inverse projection
  -> candidate cell polygon validation
  -> existing placement validation
```

시뮬레이션은 화면 투영을 알지 못하며, 렌더러와 입력 계층만 새 투영 모듈에 의존한다.

## 오류 처리와 경계 조건

- 0 이하 또는 유한하지 않은 뷰포트 크기는 기존처럼 안전한 최소값으로 정규화한다.
- 유한하지 않은 월드 좌표와 파생 화면 좌표는 렌더링하지 않는다.
- 원근 역변환이 실패하거나 셀 다각형 밖이면 입력을 무시한다.
- 이미지 에셋 로딩 실패 시 타일은 녹색·모래색 다각형으로, 엔티티는 기존 폴백 도형으로 표시한다.
- 렌더러는 캔버스 영역으로 클리핑해 확대된 캐릭터가 HUD를 덮지 않게 한다.

## 테스트 전략

### 단위 테스트

1. 대표 셀과 네 모서리에서 `world -> screen -> world` 왕복 오차를 검증한다.
2. 입구의 화면 X가 창고의 화면 X보다 작은지 검증한다.
3. 위쪽 배율보다 아래쪽 배율이 큰지 검증한다.
4. 모든 투영 셀이 게임 영역 안에 들어오는지 검증한다.
5. 클라이언트 좌표 배율이 있는 환경에서 타일 터치 역변환을 검증한다.
6. 사다리꼴 바깥 입력과 유한하지 않은 입력이 `null`인지 검증한다.
7. 모든 몬스터가 진행 방향과 관계없이 정면 스프라이트를 선택하는지 검증한다.
8. 오크·요정 정면 모션이 모든 경로 방향에서 재생되는지 검증한다.
9. 비길 타일이 녹색이고 길 타일이 모래색인지 렌더 호출을 검증한다.
10. 화면 세로 위치에 따른 엔티티 깊이 정렬을 검증한다.

### 브라우저·시각 테스트

- 844×390 가로 화면에서 게임 시작, 타워 선택, 타일 미리보기, 배치 확정 흐름 검증
- 입구 왼쪽·창고 오른쪽·전체 맵 노출 확인
- 상단 유닛보다 하단 유닛이 크게 보이는지 확인
- 몬스터가 굴곡을 지나도 계속 정면을 보는지 확인
- 타워와 캐릭터가 타일에 접지되는지 확인
- 콘솔 및 페이지 오류가 없는지 확인

## 완료 조건

1. 모바일 가로 화면에서 몬스터가 시각적으로 좌→우 이동한다.
2. 위쪽이 좁고 아래쪽이 넓은 원근감이 일관되게 적용된다.
3. 캐릭터가 현재보다 눈에 띄게 크며 전체 맵은 잘리지 않는다.
4. 길 외 타일은 녹색이고 길은 단색 모래색이다.
5. 몬스터와 후추·덕배는 항상 정면을 본다.
6. 화살 타워와 투사체 방향 추적은 유지된다.
7. 터치한 타일과 미리보기·실제 배치 타일이 일치한다.
8. 전체 단위 테스트와 프로덕션 빌드가 통과한다.
