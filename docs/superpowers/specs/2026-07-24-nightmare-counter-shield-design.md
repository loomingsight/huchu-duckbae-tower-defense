# 나이트메어 혼합 타워 봉인 방패 설계

- 작성일: 2026-07-24
- 대상 저장소: `huchu-defense-v2`
- 상태: 사용자 추천안 승인 완료
- 배포 대상: `main` → GitHub Pages

## 1. 목표

나이트메어 N3~N6에서 화살 타워만 반복 배치하는 전략으로는 스테이지를
클리어할 수 없게 하고, 슬로우 타워 또는 덕배·후추를 섞은 전략은 2별
이상으로 클리어할 수 있게 한다.

새 에셋이나 적 종류를 추가하지 않고 기존 해골 기사의 반투명 방패와
`shield-open`, `shield-block`, `shield-break` 효과를 재사용한다.

## 2. 확정된 규칙

### N1·N2

- 기존 해골 기사 방패가 피해 이벤트 세 번을 막은 뒤 해제되는 규칙을
  그대로 유지한다.
- 화살, 덕배와 후추 모두 기존처럼 방패 횟수를 한 번씩 소모한다.
- 기존 난도, 시작 골드와 특성 안내는 변경하지 않는다.

### N3~N6

- 모든 해골 기사는 `봉인 방패` 상태로 등장한다.
- 화살 타격은 피해를 주지 못하고 방패 횟수도 소모하지 않는다.
- 슬로우 타워 사정거리에 들어오면 방패가 즉시 해제된다.
- 덕배 또는 후추의 직접·스플래시 타격은 방패를 즉시 해제한다.
- 방패를 해제한 덕배·후추의 첫 타격은 피해를 주지 않는다.
- 방패가 해제된 뒤에는 모든 타워 피해가 기존 수치대로 적용된다.
- 화살이 막힐 때 `shield-block`, 해제될 때 `shield-break` 효과를
  발생시킨다.

이 규칙은 해골 기사에게만 적용한다. 분열 슬라임, 흡혈 박쥐, 흑요석 골렘과
리치의 기존 특성은 변경하지 않는다.

## 3. 최초 안내

봉인 방패가 처음 적용되는 N3에서 첫 해골 기사의 `shield-open` 이벤트를
받으면 기존 비차단 특성 안내 UI를 2.5초 동안 한 번만 표시한다.

- 제목: `해골 기사 · 봉인 방패`
- 본문: `슬로우·덕배·후추로 방패를 해제하세요`

N1의 분열·둔화 저항 안내는 그대로 유지한다. N4~N6에서는 같은 설명을
반복하지 않는다. 저장 스키마는 추가하지 않고 도전별 안내 상태만 사용한다.

## 4. 난도와 경제

N3~N6의 승인 난도 배율과 결정론적 배치 시뮬레이션 결과를 함께 적용한다.

| 스테이지 | HP | 속도 | 스폰 간격 | 수량 | 시작 골드 |
| --- | ---: | ---: | ---: | ---: | ---: |
| N3 | 1.07 | 1.01 | 1.00 | 1.00 | 360G |
| N4 | 1.13 | 1.02 | 0.98 | 1.02 | 380G |
| N5 | 1.21 | 1.03 | 0.96 | 1.05 | 480G |
| N6 | 1.30 | 1.05 | 0.94 | 1.08 | 480G |

N1·N2는 280G를 유지한다. 타워 가격, 공격력, 사정거리, 처치 보상,
창고 체력과 별점 기준은 변경하지 않는다.

## 5. 코드 경계와 데이터 흐름

### 방패 규칙

`src/game/enemies/enemyTraits.ts`가 봉인 방패 판정과 해제를 소유한다.

- `applyEnemyDamage(state, enemy, damage, sourceType?)`가 공격 타워 종류를
  받아 N3~N6 봉인 방패와 기존 방패를 구분한다.
- `disruptEnemyShield(state, enemy)`는 N3~N6 해골 기사의 활성 방패만
  한 번 해제하고 `shield-break` 이벤트를 반환한다.
- 출처가 없거나 화살인 피해는 봉인 방패를 해제하지 않는다.

`src/game/combat/updateProjectiles.ts`는 투사체의 `towerType`을
`applyEnemyDamage`에 전달한다. `src/game/combat/updateSlow.ts`는 적이
슬로우 범위 안에 있을 때 `disruptEnemyShield`를 호출한다.

### 안내

`src/app/traitNotice.ts`는 N1 기본 안내와 N3 봉인 방패 안내의 활성 조건을
분리한다. Canvas 효과와 DOM 안내는 모두 기존 이벤트 흐름을 사용한다.

## 6. 검증 계약

### 단위 계약

- N1·N2 해골 방패는 기존처럼 피해 세 번 뒤 해제된다.
- N3~N6 해골 방패는 반복 화살 타격에도 남고 HP가 줄지 않는다.
- N3~N6 해골 방패는 슬로우 범위 진입 시 해제된다.
- 덕배·후추 첫 타격은 방패만 해제하고 다음 타격부터 피해를 준다.
- N3에서만 봉인 방패 안내가 2.5초 동안 한 번 표시된다.

### 결정론적 밸런스 계약

실제 `createGame`, `placeTower`, `updateGame`, `calculateGameScore` 경로를
60fps로 최대 8분 실행한다.

- N3~N6의 건설 가능 타일을 경로 커버리지 순으로 사용하는 화살-only
  전략은 모두 `defeat`여야 한다.
- 화살 세 개 뒤 슬로우 타워를 조기에 배치하는 혼합 전략은 N3~N6에서
  모두 `victory`이며 2별 이상이어야 한다.
- N2 기존 혼합 타워 회귀 테스트도 계속 통과해야 한다.

이 시뮬레이션은 UI 조작 속도나 사람의 판단 시간을 모델링하지 않는다.
따라서 배포 후 실제 플레이 항목은 별도로 유지한다.

## 7. 예외와 안전성

- 유효하지 않거나 0 이하인 피해는 기존처럼 무시한다.
- 이미 해제됐거나 봉인 방패 대상이 아닌 적에 대한 해제 호출은 아무
  상태도 바꾸지 않는다.
- 한 프레임에 여러 슬로우 타워가 겹쳐도 `shield-break`는 한 번만
  발생한다.
- 분열체와 보스의 보상·점수·누적 통계는 변경하지 않는다.

## 8. 제외 범위

- 새 이미지·3D 에셋·오디오 제작
- 신규 적 종류와 웨이브 구성 변경
- 타워 가격·성능 변경
- 저장 데이터 마이그레이션
- 전체 E2E 실행

## 9. 완료 기준

- 화살-only N3~N6 결정론적 시뮬레이션이 모두 패배한다.
- 슬로우 혼합 N2~N6 시뮬레이션이 모두 승리하고 2별 이상이다.
- N1·N2 방패 규칙과 기존 특성 안내가 회귀하지 않는다.
- 봉인 방패의 블록·해제 효과와 N3 최초 안내가 동작한다.
- 전체 단위 테스트, 타입 검사와 프로덕션 빌드가 통과한다.
- GitHub Pages 배포가 성공하고 공개 HTML·JS·CSS가 HTTP 200을 반환한다.
