- 작성일: 2026-07-24
- 대상 저장소: `huchu-defense-v2`
- 상태: 후속 봉인 방패 설계와 함께 구현 승인 완료
- 배포 대상: `main` → GitHub Pages

## 1. 배경

나이트메어 N1과 N2는 최근 초반 그림자 슬라임과 혼합 타워 경제를
재조정했지만, N3부터는 스테이지 HP·속도·수량 증가와 스폰 간격 단축이
겹치면서 반복 도전으로도 클리어하기 어렵다는 플레이 피드백이 발생했다.

N3~N6의 몬스터 구성과 특성은 유지하면서 스테이지 공통 난도 배율의 증가
폭을 완만하게 만들어, 스테이지가 올라갈수록 어려워지는 흐름은 보존하되
혼합 타워 전략으로 안정적인 클리어가 가능하게 한다.

초기 설계의 난도 배율만 적용한 결정론적 시뮬레이션에서는 N3~N6이 각각
4·3·4·2웨이브에서 패배했다. N6 3웨이브의 화살 타격 요구량은 N2보다 약
47% 많지만 경로는 약 15% 짧고, 모든 스테이지의 시작 골드는 280G로
동일했다. 따라서 배율 완화와 함께 후반 스테이지의 초기 건설 선택지를
넓히는 시작 골드 조정이 필요하다.

## 3. 접근 방식

### 채택: 스테이지 난도 배율 완화와 시작 골드 단계 증가

`NIGHTMARE_DIFFICULTY`의 N3~N6 난도 배율과 시작 골드를 조정하고,
기존 해골 기사 방패를 N3~N6에서 혼합 타워로 해제해야 하는 봉인 방패로
확장한다. 웨이브별 수량과 몬스터 카탈로그는 변경하지 않는다.

N3부터 세 번째 화살 타워를 먼저 선택할 수 있게 하되, 슬로우 또는
덕배·후추 없이는 봉인 방패를 해제할 수 없게 한다. N5·N6의 480G는
덕배를 바로 선택하거나 화살 세 개와 슬로우를 섞는 선택지를 제공한다.

### 제외한 대안

1. 웨이브별 몬스터 수와 스폰 간격을 직접 낮추는 방식은 세밀하지만 수치가
   여러 파일과 웨이브에 분산되어 이후 조정 비용이 커진다.
2. 처치 보상을 늘리는 방식은 적 수에 따라 경제가 다시 증폭되고 별점용
   전투 점수까지 달라지므로 제외한다. 시작 골드는 스테이지별 고정값만
   늘려 이 문제를 피한다.

## 4. 난도 배율

N1과 N2는 현재 값을 유지하고 N3~N6만 다음 값으로 변경한다.

| 스테이지 | HP 현재 → 변경 | 속도 현재 → 변경 | 스폰 간격 현재 → 변경 | 수량 현재 → 변경 |
| --- | ---: | ---: | ---: | ---: |
| N1 | 1.00 → 1.00 | 1.00 → 1.00 | 1.00 → 1.00 | 1.00 → 1.00 |
| N2 | 1.04 → 1.04 | 1.00 → 1.00 | 1.00 → 1.00 | 1.00 → 1.00 |
| N3 | 1.10 → 1.07 | 1.02 → 1.01 | 0.98 → 1.00 | 1.02 → 1.00 |
| N4 | 1.20 → 1.13 | 1.03 → 1.02 | 0.96 → 0.98 | 1.05 → 1.02 |
| N5 | 1.34 → 1.21 | 1.05 → 1.03 | 0.93 → 0.96 | 1.09 → 1.05 |
| N6 | 1.46 → 1.30 | 1.07 → 1.05 | 0.90 → 0.94 | 1.12 → 1.08 |

HP 배율은 N2 이후 약 3~9%씩 증가하고, 수량과 스폰 압력은 후반으로 갈수록
점진적으로 높아진다. N6가 가장 어렵다는 순서는 유지한다.

### 4.1 시작 골드

| 스테이지 | 현재 → 변경 |
| --- | ---: |
| N1 | 280G → 280G |
| N2 | 280G → 280G |
| N3 | 280G → 360G |
| N4 | 280G → 380G |
| N5 | 280G → 480G |
| N6 | 280G → 480G |

N3은 화살 타워 세 개를 먼저 선택할 수 있고, N4부터는 화살 세 개와 슬로우
타워 한 개를 시작 시점 또는 첫 처치 직후 구성할 수 있다. 시작 골드 증가는
처치 보상과 전투 점수에 영향을 주지 않는다.

## 5. 유지할 계약

- N1과 N2의 모든 난도 배율과 기존 N2 혼합 타워 회귀 테스트를 유지한다.
- 그림자 슬라임은 본체 1마리에서 체력 17%의 자식 2마리로 한 번만
  분열한다.
- 첫 세 웨이브의 그림자 슬라임 kill value와 흑요석 골렘 기본 속도
  0.52를 유지한다.
- 몬스터와 타워 카탈로그, 창고 HP 12, 보상 배율 0.85를 변경하지 않는다.
- N1·N2 시작 골드는 280G를 유지하고 N3~N6만 승인된 값으로 변경한다.
- 2별·3별 점수 기준과 전역 웨이브 HP 증가율 0.08을 변경하지 않는다.
- 나이트메어 맵, 웨이브 구성과 오디오는 변경하지 않는다. 적 특성 변경은
  N3~N6 해골 기사의 봉인 방패에 한정하고 기존 렌더링 효과를 재사용한다.

## 6. 결정론적 클리어 검증

`tests/game/nightmareBalance.test.ts`의 N2 혼합 타워 시뮬레이션을
N3~N6까지 확장한다.

1. 각 스테이지의 실제 건설 가능 타일을 사용한다.
2. 길을 많이 덮으면서 경로 전반에 분산된 승인 배치 순서를 사용한다.
3. N2는 기존 화살 2개·슬로우 1개 시작을 유지하고, N3~N6은 화살 3개를
   먼저 배치한 뒤 슬로우 타워를 조기에 한 개 이상 배치한다.
4. 이후 골드가 모일 때마다 경로 커버리지가 높은 위치에 화살 타워를
   추가한다.
5. 실제 게임과 같은 60fps 업데이트를 최대 8분 동안 실행한다.
6. N2~N6 모두 승리하고 2별 이상을 획득하며 슬로우 타워가 실제 배치됐는지
   검증한다.

N3~N6 화살-only 전략은 경로 커버리지 상위 타일을 사용해도 모두
`defeat`여야 한다. 배포 후 공개 게임에서도 화살-only 차단과 혼합 구성의
실제 체감을 확인한다.

## 7. 데이터 흐름과 오류 처리

1. `getStageDefinition`이 조정된 `NIGHTMARE_DIFFICULTY`와 시작 골드를
   읽는다.
2. `createNightmareWaves`가 수량 배율을 적용해 기존 웨이브를 생성한다.
3. `spawnEnemy`와 `updateWaves`가 HP·속도·스폰 간격 배율을 기존 순서로
   적용한다.
4. `createGame`이 스테이지별 시작 골드로 새 게임을 초기화한다.
5. 피해 처리와 슬로우 처리가 N3~N6 봉인 방패의 블록·해제를 판정한다.
6. 결정론적 시뮬레이션이 실제 `createGame`, `placeTower`, `updateGame`,
   `calculateGameScore` 경로를 사용해 결과를 검증한다.

설정 값은 정적 상수이며 새 사용자 입력이나 저장 스키마가 생기지 않으므로
별도의 런타임 오류 처리와 마이그레이션은 필요하지 않다.

## 8. 테스트와 검증

### RED

- N3~N6 승인 배율을 기대하는 스테이지 카탈로그 테스트를 먼저 추가하고
  현재 값에서 실패하는지 확인한다.
- N1~N6 승인 시작 골드를 기대하는 테스트를 추가하고 N3~N6의 기존
  280G에서 실패하는지 확인한다.
- N3~N6 혼합 타워 클리어 시뮬레이션을 추가하고 현재 난도에서 실패하는
  스테이지가 있음을 확인한다.
- N3~N6 화살-only 시뮬레이션과 봉인 방패 상호작용 테스트를 추가하고
  기존 방패 규칙에서는 화살-only가 통과하는 스테이지가 있음을 확인한다.

### GREEN

- `NIGHTMARE_DIFFICULTY`의 N3~N6 배율과 시작 골드를 승인 값으로 변경하고
  봉인 방패 블록·해제와 N3 최초 안내를 구현한다.
- 집중 테스트가 모두 통과할 때까지 구현 코드가 아닌 승인된 배율 적용과
  시뮬레이션 빌드 순서의 현실성만 점검한다.

- 관련 Vitest 집중 실행

  `/huchu-duckbae-tower-defense/`로 시작하는지 확인

## 9. 배포 후 실제 플레이

1. `main` 푸시 후 GitHub Actions Pages 배포가 `success`인지 확인한다.
2. 공개 HTML과 주요 JS·CSS 번들이 HTTP 200인지 확인한다.
3. 공개 게임에서 화살-only가 봉인 방패를 해제하지 못하고, 슬로우 혼합
   구성은 2~3별로 진행 가능한지 확인한다.
4. 확인 결과를 `docs/backlog.md`에 반영하고 두 미완료 밸런스 항목을
   완료 처리한다.

## 10. 완료 기준

- N3~N6 난도 배율이 승인 표와 일치하고 단계별 증가 순서를 유지한다.
- N1·N2 시작 골드와 처치 보상, 점수 기준, 적·타워 개별 수치가 바뀌지
  않는다.
- N3~N6 시작 골드는 360/380/480/480G다.
- N2~N6 혼합 타워 결정론적 시뮬레이션이 승리와 2별 이상을 보장한다.
- N3~N6 화살-only 결정론적 시뮬레이션이 모두 패배한다.
- 전체 단위 테스트, 타입 검사와 프로덕션 빌드가 통과한다.
- GitHub Pages 배포와 공개 리소스 응답을 확인한다.
- 배포 후 실제 플레이 결과를 기록하고 밸런스 백로그를 완료 처리한다.
