# 전투 피드백 및 타워 패널 위치 전환 설계

상태: **사용자 승인 완료**

## 목표

플레이 중 화면을 오래 가리는 중앙 안내를 3초 안에 정리하고, 간식 창고
피격의 타격감을 강화하며, 모바일 사용자가 타워 선택 패널 위치를 직접
바꿀 수 있게 한다.

## 승인된 접근

기존 DOM HUD와 시뮬레이션 이벤트 경계를 유지하는 최소 변경 방식을
사용한다.

- 중앙 안내는 `placement-status` 전용 타이머 컨트롤러로 관리한다.
- 창고 피격은 이미 프레임 버퍼에 기록되는 `leak` cue를 사용한다.
- 타워 패널 위치는 HUD의 독립 버튼과 저장 가능한 UI 설정으로 관리한다.

Canvas 내부에 안내와 흔들림을 새로 그리는 방식은 DOM 접근성을 잃고,
패널 위치를 자동 감지하는 방식은 기기별 맵 구성이 달라 오판 가능성이
높아 제외한다.

## 중앙 안내 메시지

대상은 게임 보드 위에 표시되는 비차단 `placement-status`이다. 스테이지
선택·결과 모달과 별도 특성 안내인 `trait-notice`는 바꾸지 않는다.

- 메시지를 표시할 때 이전 만료 타이머를 취소한다.
- 마지막 메시지 표시로부터 정확히 3,000ms 뒤 텍스트를 비우고 요소를
  숨긴다.
- 빈 메시지는 화면과 접근성 트리에서 보이지 않는다.
- 새 게임 시작, 타워 선택·취소, 배치 미리보기·확정·취소, 잘못된 배치
  안내가 모두 같은 컨트롤러를 사용한다.
- 앱 종료 시 타이머를 해제한다.

## 간식 창고 피격 흔들림

시뮬레이션은 창고 체력이 감소한 프레임을 이미 `leak` cue로 기록한다.
렌더 단계에서 해당 cue를 소비할 때 `game-shell`에 피격 클래스를
재적용한다.

- 애니메이션 길이는 420ms이다.
- Canvas, HUD, 타워 패널을 포함한 전체 `game-shell`이 함께 흔들린다.
- 연속 피격 시 클래스를 제거한 뒤 reflow하고 다시 추가해 애니메이션을
  처음부터 재생한다.
- 460ms 뒤 클래스를 정리하며 앱 종료과 새 게임 시작에서도 남지 않게
  한다.
- `prefers-reduced-motion: reduce`에서는 흔들림 애니메이션을 실행하지
  않는다.

## 모바일 타워 패널 위치 전환

모바일 가로 화면 조건인 `orientation: landscape`, 최대 너비 1024px,
최대 높이 430px에서만 44×44px 위치 전환 버튼을 노출한다.

- 기본 위치는 기존 하단 중앙이다.
- 버튼을 누르면 타워 패널을 상단 중앙으로 이동하고 다시 누르면 하단으로
  복귀한다.
- 하단일 때 버튼은 `타워 버튼 위로 이동`, 상단일 때는
  `타워 버튼 아래로 이동`이라는 접근성 이름과 방향 아이콘을 가진다.
- 위치 값은 기존 preferences v4에 `towerTrayPosition: 'bottom' | 'top'`
  필드로 저장한다. 기존 저장 데이터나 잘못된 값은 `bottom`으로
  정규화한다.
- 위치 변경은 게임 진행·일시정지 상태를 바꾸지 않고 즉시 렌더링한다.
- 세로 화면, 데스크톱, 스테이지 선택 모달에서는 기존 레이아웃을
  방해하지 않는다.

## 파일 경계

- `src/app/transientMessage.ts`: 3초 메시지 타이머 컨트롤러
- `src/app/baseHitFeedback.ts`: 반복 실행 가능한 창고 피격 클래스 컨트롤러
- `src/app/preferences.ts`: 타워 패널 위치 타입·정규화·저장
- `src/app/hud.ts`: 위치 전환 버튼과 HUD 상태 반영
- `src/app/GameApp.ts`: 메시지 컨트롤러, leak 흔들림, 위치 전환 이벤트 연결
- `src/styles.css`: 빈 메시지 숨김, 피격 애니메이션, 모바일 패널 위치
- `tests/app/transientMessage.test.ts`: 타이머 갱신·만료·정리
- `tests/app/baseHitFeedback.test.ts`: 피격 재시작·만료·정리
- `tests/app/preferences.test.ts`: 기존 값 이전과 위치 저장
- `tests/app/hud.test.ts`: 버튼 문구와 위치 상태
- `tests/scaffold.test.ts`: 흔들림·모바일 레이아웃 CSS 계약

## 검증 및 배포

- 각 기능을 실패 테스트부터 작성하고 RED를 확인한 뒤 구현한다.
- `npm run test`, `npm run build`, `git diff --check`를 통과시킨다.
- 모바일 가로 뷰포트에서 메시지 만료, 피격 흔들림 클래스, 패널 상·하단
  전환을 수동 확인한다.
- 기존 승인에 따라 E2E 테스트는 실행하지 않는다.
- `main` 푸시 후 GitHub Pages 실행 성공과 공개 HTML·JS HTTP 200을
  확인한다.

## 제외 범위

- 메시지 큐 또는 여러 메시지 동시 표시
- 패널과 맵 오브젝트의 자동 충돌 판정
- 흔들림 강도 사용자 설정
- 게임 밸런스와 에셋 변경
